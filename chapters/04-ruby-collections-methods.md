# 第4章 Ruby入門2：配列・Hash・メソッド・ブロック

> **この章のゴール**：配列と Hash でデータをまとめて扱い、メソッドとブロックを使って、処理を名前の付いた部品に分けられる。
> **目安時間**：読む 3時間 ＋ 演習 5時間
> **前提**：第3章まで

## この章で学ぶこと

- 配列と Hash を作り、要素の取り出し・追加・削除・検索ができる
- `each` / `map` / `select` / `find` / `sum` などを使い分け、ループを書かずに集計できる
- 「配列の中に Hash」という形で、表のようなデータを扱える
- メソッドを定義し、引数（デフォルト値・キーワード引数）と戻り値を使える
- `yield` を使ってブロックを受け取るメソッドを書き、ブロックの仕組みを説明できる
- 変数が「名札」であることと、破壊的な変更がどこまで影響するかを説明できる

## なぜ「まとめて扱う」必要があるのか

第3章では、1つの変数に1つの値を入れました。しかし、実際のプログラムが扱うデータは、たいてい「たくさん」あります。クラス全員の点数、商品の一覧、ブログの記事の一覧、などです。

`score1 = 72`、`score2 = 95`、`score3 = 48` …… と変数を増やすやり方では、人数が変わるたびにプログラムを書き換える必要があります。平均を出すのも大変です。

そこで、値をまとめて入れる入れ物を使います。この入れ物を**コレクション**と呼びます。Ruby で最もよく使うのが、**配列（Array）**と **Hash（ハッシュ）**です。

- **配列**：値を**順番に**並べた入れ物。番号で取り出す。電車の座席のようなもの
- **Hash**：値に**名前（キー）**を付けて入れる入れ物。名前で取り出す。辞書や名簿のようなもの

後の章で作る Web アプリでは、データベースから取り出した記事の一覧が配列で、1つの記事の「タイトル」「本文」が Hash のような形で届きます。この章で学ぶ操作は、Web アプリのほぼすべての画面で使います。

## 配列（Array）

### 作る・取り出す

配列は `[ ]` で作り、要素をカンマで区切ります。

```ruby
fruits = ["りんご", "みかん", "ぶどう"]
p fruits[0]
p fruits[2]
p fruits[-1]
p fruits[5]
p fruits.length
```

```text
"りんご"
"ぶどう"
"ぶどう"
nil
3
```

`fruits[0]` のように、`[番号]` で要素を取り出します。この番号を**インデックス**と呼びます。第3章の `times` と同じく、**0 から数えます**。最初の要素が `[0]`、3番目が `[2]` です。

マイナスの番号は、後ろから数えます。`[-1]` は最後の要素です。

存在しない番号を指定すると、エラーではなく `nil` が返ります。ここは注意が必要です。エラーにならないので、間違いに気付きにくいのです。後で `nil` に対してメソッドを呼んだときに初めてエラーになり、原因を探すのに苦労します。

配列には、どんな型の値でも入れられます。型を混ぜることもできます。

```ruby
mixed = [1, "two", :three, 4.0, nil, [5]]
p mixed
```

```text
[1, "two", :three, 4.0, nil, [5]]
```

ただし、実際のプログラムでは、1つの配列には同じ種類のもの（全部が点数、全部が商品、など）を入れるのが普通です。そのほうが、まとめて同じ処理をしやすいからです。

### メソッドの読み方（第3章の復習）

この章では、`fruits.length` のような**メソッド**がたくさん出てきます。第3章で見たとおり、メソッドは「値に対してできる操作」です。初めのうちは、**値に「これをして」と頼むお願い**だと考えると読みやすくなります。

```text
fruits  .  length
└ 左 ┘     └ 右 ┘
 値         メソッド（お願いの種類）
```

`.`（ドット）の左にあるのが、お願いされる値です。`fruits` のような変数（値に付けた名前）が来ることもあります。右にあるのがメソッドです。`"ruby".upcase` は「`"ruby"` さん、大文字にして」、`fruits.length` は「`fruits` さん、何個あるか教えて」と読めます。

値の種類ごとに、聞けるお願い（使えるメソッド）が決まっています。配列なら `length` や `sort`、文字列なら `upcase` や `to_i` です。

コードの意味がつかみにくいときは、1行ずつ日本語のお願いに言い換えてみてください。この章でも、ところどころで「日本語で読むと」として言い換えを添えます。

### 追加・削除

```ruby
fruits = ["りんご", "みかん", "ぶどう"]
fruits << "もも"
fruits.push("なし")
p fruits
p fruits.pop
p fruits.shift
p fruits
fruits.unshift("いちご")
p fruits
```

```text
["りんご", "みかん", "ぶどう", "もも", "なし"]
"なし"
"りんご"
["みかん", "ぶどう", "もも"]
["いちご", "みかん", "ぶどう", "もも"]
```

| メソッド | 意味 |
|---|---|
| `<<` / `push` | 末尾に追加する |
| `pop` | 末尾から1つ取り出す（配列からは消える） |
| `shift` | 先頭から1つ取り出す（配列からは消える） |
| `unshift` | 先頭に追加する |

`pop` と `shift` は、取り出した値を返すと同時に、配列からその要素を消します。

列に並んだ人で考えると覚えやすくなります。`push` は列の最後に並ぶ、`pop` は最後の人が抜ける、`shift` は先頭の人が抜ける（順番が来た）、`unshift` は先頭に割り込む、です。

### 調べる・切り出す・並べる

```ruby
fruits = ["いちご", "みかん", "ぶどう", "もも"]
p fruits.include?("みかん")
p fruits.index("ぶどう")
p fruits.first
p fruits.last(2)
p fruits[1, 2]
p fruits[1..2]
p fruits.join("、")
```

```text
true
2
"いちご"
["ぶどう", "もも"]
["みかん", "ぶどう"]
["みかん", "ぶどう"]
"いちご、みかん、ぶどう、もも"
```

`fruits[1, 2]` は「1番目から2個」、`fruits[1..2]` は「1番目から2番目まで」です。`join` は、要素を指定した文字でつないで1つの文字列にします。第3章の `split` の逆です。

数の配列には、次のようなメソッドもよく使います。

```ruby
p [3, 1, 2].sort
p [3, 1, 2].reverse
p [1, [2, 3], [4]].flatten
p [1, 2, 2, 3, 3, 3].uniq
p [1, nil, 2, nil].compact
p [1, 2, 3].sum
p [5, 3, 9].max
p [5, 3, 9].min
p [].first
```

```text
[1, 2, 3]
[2, 1, 3]
[1, 2, 3, 4]
[1, 2, 3]
[1, 2]
6
9
3
nil
```

`flatten` は入れ子の配列を平らにし、`uniq` は重複を取り除き、`compact` は `nil` を取り除きます。空の配列の `first` が `nil` になるのも、覚えておいてください。

`reverse` は、並べ替えるのではなく、**今の並びをそのまま逆にする**だけです。`[3, 1, 2]` を逆にすると `[2, 1, 3]` で、大きい順にはなりません。

### 破壊的メソッドと `!`

```ruby
nums = [3, 1, 2]
sorted = nums.sort
p nums
p sorted
nums.sort!
p nums
```

```text
[3, 1, 2]
[1, 2, 3]
[1, 2, 3]
```

`sort` は、並べ替えた**新しい配列**を返し、元の配列は変えません。`sort!` は、**元の配列そのもの**を並べ替えます。元のデータを変えてしまうメソッドを、**破壊的メソッド**と呼びます。

Ruby では、同じ働きで破壊的なものと非破壊的なものがあるとき、破壊的なほうに `!` を付ける習慣があります。`!` は「注意して使ってね」という目印です。ただし、`<<` や `push`、`pop` のように、`!` が付いていなくても元の配列を変えるメソッドもあります。名前だけで判断せず、迷ったら irb で確かめてください。

基本的には、**非破壊的なメソッドを使い、結果を新しい変数に入れる**ほうが安全です。なぜ安全なのかは、この章の後半「変数は名札」で説明します。

## 配列をブロックで処理する

### each：1つずつ取り出す

配列の要素を1つずつ処理するには、`each` を使います。

```ruby
scores = [72, 95, 48, 88, 60]

scores.each do |s|
  puts "点数: #{s}"
end

scores.each_with_index do |s, i|
  puts "#{i + 1}番目: #{s}"
end
```

```text
点数: 72
点数: 95
点数: 48
点数: 88
点数: 60
1番目: 72
2番目: 95
3番目: 48
4番目: 88
5番目: 60
```

`each` は、配列の要素を先頭から順に取り出し、`|s|` に入れて、ブロック（`do ... end` の中）を実行します。ベルトコンベアに乗って流れてくる品物を、1つずつ手に取って作業するイメージです。`each_with_index` は、要素と一緒に番号（0 から）も渡してくれます。

日本語で読むと、最初の `each` は次のようになります。

```text
scores.each do |s|          「scores さん、中身を1つずつ渡して。渡されたものを s と呼ぶね」
  puts "点数: #{s}"          「1つごとに『点数: （s）』と表示して」
end
```

`|s|` の `s` は自分で決める名前です。`do ... end` の代わりに `{ }` を使って、`scores.each { |s| puts "点数: #{s}" }` と1行で書くこともできます。意味は同じです。

他の言語では、`for (i = 0; i < n; i++)` のように番号を数えながら繰り返す書き方がよく使われます。Ruby では、番号を自分で管理する書き方はほとんどしません。番号の数え間違い（1つ多い・少ない）というバグを、そもそも起こさないためです。

### map・select・reject・find

`each` で何でもできますが、Ruby には「よくある目的」ごとに専用のメソッドがあります。目的に合ったメソッドを使うと、プログラムが短く、読みやすくなります。

```ruby
scores = [72, 95, 48, 88, 60]
p scores.map { |s| s + 5 }
p scores.select { |s| s >= 70 }
p scores.reject { |s| s >= 70 }
p scores.find { |s| s < 60 }
p scores.count { |s| s >= 60 }
p scores.any? { |s| s == 100 }
p scores.all? { |s| s >= 40 }
```

```text
[77, 100, 53, 93, 65]
[72, 95, 88]
[48, 60]
48
4
false
true
```

| メソッド | 何を返すか | たとえると |
|---|---|---|
| `map` | 各要素をブロックで変換した**新しい配列** | 全員の点数に5点足した名簿を作る |
| `select`（`filter`） | ブロックが真になった要素だけの配列 | 70点以上の人だけ集める |
| `reject` | ブロックが偽になった要素だけの配列 | 70点以上の人を除く |
| `find` | ブロックが真になった**最初の1つ**（なければ `nil`） | 60点未満の人を1人見つける |
| `count` | ブロックが真になった数 | 合格者の数を数える |
| `any?` / `all?` | 1つでも真か / すべて真か | 満点の人はいるか / 全員40点以上か |

どれも、元の配列は変えません。

日本語で読むと、`select { |s| s >= 70 }` は「1つずつ s として受け取って、70 以上かどうかを答えて。真になったものだけ残して」です。`>=` は「以上」なので 70 も残ります。`s > 70` と書くと「70 より大きい」になり、70 ちょうどは残りません。`select` と `reject` は表と裏の関係で、同じ条件なら、2つの結果を合わせると元の配列の全部になります。

`select` と `find` の違いにも注意してください。`select` は条件に合うものを**全部**集めて配列で返し、`find` は**最初の1つだけ**をそのまま返します。

`map` と `each` の違いは、特に大事です。`each` は「処理をすること」が目的で、戻り値は元の配列のままです。`map` は「変換した結果を集めること」が目的です。「各要素を変換した配列がほしい」のに `each` を使い、空の配列に `<<` で詰めていく書き方は、`map` で1行になります。

`map` は変換したものを**並べて返すだけ**で、足し算はしません。合計がほしいときは `sum` を使います。

```ruby
p [3, 5].map { |n| n * 10 }
p [3, 5].sum
```

```text
[30, 50]
8
```

`map` の結果は、元と同じ数の要素が入った配列です。`sum` の結果は、1つの数です。

### 集計：sum・inject・sort_by・min_by

```ruby
scores = [72, 95, 48, 88, 60]
p scores.sum / scores.length
p scores.sum.fdiv(scores.length)
p scores.sort.reverse
p scores.sort_by { |s| -s }
p scores.inject(0) { |total, s| total + s }
p scores.min_by { |s| (s - 70).abs }
p scores.each_slice(2).to_a
p scores.partition { |s| s >= 60 }
```

```text
72
72.6
[95, 88, 72, 60, 48]
[95, 88, 72, 60, 48]
363
72
[[72, 95], [48, 88], [60]]
[[72, 95, 88, 60], [48]]
```

1行目に注意してください。`sum`（363）も `length`（5）も整数なので、割り算の結果は切り捨てられて `72` になります。第3章で学んだとおりです。正しい平均は、`fdiv` で `72.6` です。

- `sort_by`：ブロックの結果を基準に並べ替えます。`-s` を基準にすると、大きい順になります。
- `inject`：値を1つにまとめていきます。`total` に「これまでの合計」、`s` に次の要素が入り、ブロックの結果が次の `total` になります。`sum` で済むときは `sum` を使えばよいのですが、`inject` は「まとめ方」を自分で決められる汎用の道具です。
- `min_by` / `max_by`：ブロックの結果が最小 / 最大になる要素を**1つだけ**返します。上の例は「70 に一番近い点数」です。全部を並べ替えるのではありません。
- `each_slice(2)`：2個ずつに区切ります。
- `partition`：条件で2つのグループに分けます。`[条件に合ったもの, 合わなかったもの]` の順で、**両方**を返します。`select` の結果と `reject` の結果を、一度にもらえると考えてください。

`sort_by`・`min_by`・`max_by` のように `_by` が付くメソッドは、「何を基準にするか」をブロックで決めます。

`inject` の動きを1つずつ追うと、次のようになります。

```text
total=0    s=72  → 0 + 72    = 72
total=72   s=95  → 72 + 95   = 167
total=167  s=48  → 167 + 48  = 215
total=215  s=88  → 215 + 88  = 303
total=303  s=60  → 303 + 60  = 363
```

Ruby 2.7 以降には、要素ごとの出現回数を数える `tally` や、変換と絞り込みを同時に行う `filter_map` もあります。この教材の推奨環境（Ruby 3.3 以降）では使えるので、irb で試してみてください。

### `&:メソッド名` の省略形

ブロックの中で「各要素のメソッドを1つ呼ぶだけ」のときは、短く書けます。

```ruby
p %w[apple banana cherry].map(&:upcase)
p %w[apple banana cherry].map { |w| w.length }
p((1..10).select(&:even?))
```

```text
["APPLE", "BANANA", "CHERRY"]
[5, 6, 6]
[2, 4, 6, 8, 10]
```

`map(&:upcase)` は `map { |w| w.upcase }` と同じ意味です。`%w[apple banana cherry]` は、`["apple", "banana", "cherry"]` を短く書く記法です。Rails のコードでは、この省略形がとてもよく出てきます。読めるようにしておいてください。

## Hash

### 作る・取り出す

Hash は `{ }` で作り、`キー: 値` の組をカンマで区切ります。

```ruby
user = { name: "Taro", age: 20, city: "Tokyo" }
p user
p user[:name]
p user[:email]
```

```text
{:name=>"Taro", :age=>20, :city=>"Tokyo"}
"Taro"
nil
```

`user[:name]` のように、`[キー]` で値を取り出します。存在しないキーを指定すると、配列と同じく `nil` が返ります。

`p` の出力が `{:name=>"Taro", ...}` という形になっていることに注目してください。`:name` はシンボル（第3章）で、`=>` は「キーと値の対応」を表す記号です。`{ name: "Taro" }` は、`{ :name => "Taro" }` の省略記法なのです。なお、**Ruby 3.4 以降では、`p` の表示が `{name: "Taro", age: 20, city: "Tokyo"}` という形に変わりました**。中身は同じです。この教材の出力例は Ruby 2.6 で実行したものなので、自分の環境と見た目が違っても驚かないでください。

### 追加・変更・削除

```ruby
user = { name: "Taro", age: 20, city: "Tokyo" }
user[:email] = "taro@example.com"
user[:age] = 21
p user
p user.keys
p user.values
p user.key?(:city)
p user.length
user.delete(:city)
p user
```

```text
{:name=>"Taro", :age=>21, :city=>"Tokyo", :email=>"taro@example.com"}
[:name, :age, :city, :email]
["Taro", 21, "Tokyo", "taro@example.com"]
true
4
{:name=>"Taro", :age=>21, :email=>"taro@example.com"}
```

`user[キー] = 値` で、キーがなければ追加、あれば上書きです。`example.com` は、説明やテストのために予約されたドメインです。この教材では、メールアドレスの例には必ずこれを使います。本物のアドレスは使いません。

`keys` はキー（名前の側）だけ、`values` は値の側だけを、それぞれ配列で返します。中身の全部（キーと値の組）を見たいときは、Hash をそのまま `p` します。

`user[:city]` と `user.key?(:city)` は、聞いていることが違います。

| 書き方 | 聞いていること | 返ってくるもの |
|---|---|---|
| `user[:city]` | `:city` の値は何？ | 値そのもの（`"Tokyo"`） |
| `user.key?(:city)` | `:city` というキーはある？ | `true` か `false` だけ |

`?` で終わるメソッドは、「はい」か「いいえ」でしか答えません。名簿で「田中さんの電話番号は？」と聞くのと、「田中さんは名簿に載ってる？」と聞くのとの違いです。

### 文字列のキーとシンボルのキー

キーには、シンボルだけでなく文字列も使えます。ただし、**`"name"` と `:name` は別のキー**です。

```ruby
old_style = { "name" => "Hanako" }
p old_style["name"]
p old_style[:name]
```

```text
"Hanako"
nil
```

文字列のキーで入れたものを、シンボルのキーで取り出そうとすると `nil` になります。エラーにならないので、気付きにくいバグです。

なぜ2種類あるのでしょうか。シンボルは「プログラムの中で使う名前」、文字列は「外から来たデータ」に向いています。Web アプリでは、フォームや URL から届くパラメータは文字列のキーで、プログラムの中で作る設定などはシンボルのキーで書くことが多いです。第14章でフレームワークを自作するとき、この違いをどう扱うかを自分で決めることになります。

### 存在しないキー：nil と fetch

存在しないキーで `nil` が返るのは、間違いに気付きにくい原因になります。「このキーは必ずあるはずだ」というときは、`fetch` を使います。

```ruby
user = { name: "Taro" }
p user.fetch(:name)
p user.fetch(:phone, "未登録")
```

```text
"Taro"
"未登録"
```

`fetch` の2つ目の引数は、キーがないときの代わりの値です。日本語で読むと、`user.fetch(:phone, "未登録")` は「`:phone` の値をちょうだい。もしなかったら、代わりに `"未登録"` でいいよ」です。キーがあるときは、代わりの値は使われません。代わりの値を指定せずに、ないキーを `fetch` すると、エラーになります。次の2行を `fetch.rb` として実行してみます。

```ruby
user = { name: "Taro" }
user.fetch(:phone)
```

```text
fetch.rb:2:in `fetch': key not found: :phone (KeyError)
	from fetch.rb:2:in `<main>'
```

まとめると、次のとおりです。

| 書き方 | キーがあるとき | キーがないとき |
|---|---|---|
| `user[:phone]` | 値 | `nil`（黙って進む） |
| `user.fetch(:phone, "未登録")` | 値 | 代わりの値 `"未登録"` |
| `user.fetch(:phone)` | 値 | エラー（`KeyError`） |

「エラーになるほうが良い」というのは、意外に感じるかもしれません。しかし、間違いがあるなら、**その場ですぐ止まってくれるほうが、原因を見つけやすい**のです。`nil` のまま処理が進むと、ずっと後のまったく別の場所でエラーになり、原因を探すのが大変になります。これを「早く失敗する（fail fast）」という考え方と呼びます。

### Hash を繰り返す

```ruby
prices = { "りんご" => 150, "みかん" => 80, "ぶどう" => 400 }
prices.each do |fruit, price|
  puts "#{fruit}は#{price}円"
end
p prices.select { |_fruit, price| price >= 100 }
p prices.map { |fruit, price| "#{fruit}:#{price}" }
p prices.sort_by { |_fruit, price| price }
p prices.min_by { |_fruit, price| price }
p prices.sum { |_fruit, price| price }
p prices.transform_values { |price| price * 110 / 100 }
p prices.merge({ "もも" => 300 })
```

```text
りんごは150円
みかんは80円
ぶどうは400円
{"りんご"=>150, "ぶどう"=>400}
["りんご:150", "みかん:80", "ぶどう:400"]
[["みかん", 80], ["りんご", 150], ["ぶどう", 400]]
["みかん", 80]
630
{"りんご"=>165, "みかん"=>88, "ぶどう"=>440}
{"りんご"=>150, "みかん"=>80, "ぶどう"=>400, "もも"=>300}
```

Hash の `each` は、ブロックにキーと値の2つを渡します。配列で学んだ `select` や `map` も、Hash に使えます。

日本語で読むと、最初の `each` は「prices さん、中身を1組ずつ渡して。組のキーを fruit、値を price と呼ぶね。1組ごとに『（fruit）は（price）円』と表示して」です。`|キー, 値|` の順で受け取ります。

いくつか注意点があります。

- 使わないブロック引数には、`_fruit` のように `_` を付けます。「使っていないのはわざとです」という目印です。
- `select` は Hash を返しますが、`map` と `sort_by` は**配列**を返します。`sort_by` の結果は `[キー, 値]` の組の配列です。`select` で残るのはキーだけではなく、**キーと値の組**です。
- `min_by` は、基準が最小になる**1組だけ**を `[キー, 値]` の形で返します。
- `transform_values` は、キーはそのままで、値だけを変換した新しい Hash を返します。ブロックの結果が、そのまま新しい値になります。`{ |price| price + 100 }` なら元の値に 100 を足した値、`{ |price| 100 }` なら全部 100 です。ここでは消費税10%を、整数の計算（`* 110 / 100`、端数は切り捨て）で足しています。第3章で学んだとおり、お金に小数は使いません。
- Hash は、入れた順番を覚えています。`each` は入れた順に取り出します。

### 数える：Hash.new(0)

「単語ごとの出現回数」のような集計は、Hash の得意分野です。

```ruby
counts = Hash.new(0)
%w[a b a c a b].each { |w| counts[w] += 1 }
p counts
p counts["z"]
```

```text
{"a"=>3, "b"=>2, "c"=>1}
0
```

`Hash.new(0)` は、「ないキーを取り出したら `0` を返す」Hash を作ります。普通の Hash だと、初めて出てきた単語では `counts[w]` が `nil` になり、`nil + 1` でエラーになります。初期値を `0` にしておけば、`counts[w] += 1` だけで数えられます。

`counts[w] += 1` は `counts[w] = counts[w] + 1` の短い書き方です。動きを1つずつ追うと、次のようになります。

| 渡された w | 増やす前の `counts[w]` | 増やした後 |
|---|---|---|
| a | 0（まだない → 0） | a: 1 |
| b | 0（まだない → 0） | b: 1 |
| a | 1 | a: 2 |
| c | 0（まだない → 0） | c: 1 |
| a | 2 | a: 3 |
| b | 1 | b: 2 |

## 配列と Hash を組み合わせる

実際のデータは、「配列の中に Hash が並ぶ」形になることがよくあります。表計算ソフトの表を思い浮かべてください。1行が1つの Hash、行の集まりが配列です。

```ruby
students = [
  { name: "Aoi", score: 82, club: "soccer" },
  { name: "Ken", score: 67, club: "music" },
  { name: "Mio", score: 91, club: "soccer" },
]

p students.map { |s| s[:name] }
best = students.max_by { |s| s[:score] }
puts "最高点は#{best[:name]}さん（#{best[:score]}点）"
p students.select { |s| s[:club] == "soccer" }.map { |s| s[:name] }
grouped = students.group_by { |s| s[:club] }
p grouped.keys
p grouped["soccer"].length
average = students.sum { |s| s[:score] }.fdiv(students.length)
puts "平均: #{average.round(1)}"
students.sort_by { |s| -s[:score] }.each_with_index do |s, i|
  puts "#{i + 1}位 #{s[:name].ljust(4)} #{s[:score].to_s.rjust(3)}点"
end
```

```text
["Aoi", "Ken", "Mio"]
最高点はMioさん（91点）
["Aoi", "Mio"]
["soccer", "music"]
2
平均: 80.0
1位 Mio   91点
2位 Aoi   82点
3位 Ken   67点
```

ここでの見どころは3つあります。

その前に、取り出し方を確認しておきます。`students[0]` は「0番目の行（Hash）をちょうだい」、`students[0][:name]` は「0番目の行の、`:name` の値をちょうだい」です。`[0]` で配列から1行を取り出し、続けて `[:name]` でその Hash から値を取り出します。ブロックの中の `s` にも、1行分の Hash が入ります。

1つ目は、**メソッドをつなげて書ける**ことです。`select { ... }.map { ... }` は、「サッカー部の人を選び、その名前だけを取り出す」です。左から右へ、データが加工されていく流れとして読めます。これを**メソッドチェーン**と呼びます。途中の結果は次のとおりです。

```text
select の後 → サッカー部の2行（Aoi と Mio の Hash）
map の後    → ["Aoi", "Mio"]
```

2つ目は、`group_by` です。ブロックの結果ごとに、要素をグループに分けた Hash を返します。「部活ごとの名簿」が一度で作れます。

`group_by` は、段ボール箱に品物を仕分ける作業にたとえられます。「1人ずつ手に取って club を見て、同じ club の箱に入れていって。箱がなければ、その club の名前を書いた新しい箱を作って」という動きです。

| 手に取った人 | club を見る | どうする |
|---|---|---|
| Aoi | soccer | 「soccer」の箱がない → 箱を作って Aoi を入れる |
| Ken | music | 「music」の箱がない → 箱を作って Ken を入れる |
| Mio | soccer | 「soccer」の箱がある → そこに Mio を入れる |

結果の Hash では、キーが**箱に書いた名前**、値が**箱の中身**（その箱に入った行の配列）です。`grouped.keys` は「箱の名前を全部教えて」、`grouped["soccer"].length` は「soccer の箱には何人入っている？」という意味になります。

3つ目は、`ljust` と `rjust` です。文字列を指定した幅に左寄せ・右寄せして、表の見た目をそろえます。

この形のデータは、第15章以降のデータベースと深くつながります。データベースの表から取り出した行の集まりを、プログラムではこのような形で扱います。第16章では、この「Hash の行」を、もっと扱いやすい形に変える仕組み（ORM）を自分で作ります。

## メソッドを定義する

### def と戻り値

これまで `upcase` や `map` など、Ruby に最初からあるメソッドを使ってきました。メソッドは自分で作ることもできます。

```ruby
def greet(name)
  "こんにちは、#{name}さん"
end

puts greet("Taro")
message = greet "Hanako"
p message
```

```text
こんにちは、Taroさん
"こんにちは、Hanakoさん"
```

`def メソッド名(引数)` から `end` までが、メソッドの定義です。**引数**は、メソッドに渡す値を受け取る変数です。

メソッドが返す値（**戻り値**）は、**最後に評価された式の値**です。上の `greet` では、文字列の式が最後なので、その文字列が戻り値になります。`return` と書かなくても値が返るのが、Ruby の特徴です。

メソッドを呼ぶときの括弧は省略できます（`greet "Hanako"`）。ただし、引数があるときは括弧を付けたほうが読みやすいことが多いです。

なぜメソッドを作るのでしょうか。理由は3つあります。

1. **名前を付けられる**：`(price * 110 / 100)` より `tax_included(price)` のほうが、何をしているかが伝わります。
2. **繰り返し書かなくて済む**：同じ処理を何か所にも書くと、直すときに全部直す必要があります。直し忘れはバグになります。
3. **部品として確かめられる**：小さなメソッドは、単独で動きを確かめられます。第6章で学ぶテストは、メソッドの単位で書くのが基本です。

### return：途中で返す

途中でメソッドを終わらせたいときは、`return` を使います。

```ruby
def grade(score)
  return "不正な点数" if score < 0 || score > 100

  if score >= 80
    "A"
  elsif score >= 60
    "B"
  else
    "C"
  end
end
p grade(85)
p grade(-1)
```

```text
"A"
"不正な点数"
```

最初に「おかしな入力」をはじいて、すぐに返す書き方を**ガード節**と呼びます。おかしな場合の処理を先に片付けておくと、残りの部分は「正しい入力」だけを考えて書けます。読む人にとっても、前提がはっきりします。

`if` 全体が値を返すので、`if` の各分岐の最後の値（`"A"` など）が、そのまま戻り値になっています。第3章で「`if` も値を返す式」と学んだことが、ここで生きています。

### 引数のいろいろ

引数には、省略したときの値（**デフォルト値**）を決められます。

```ruby
def tax_included(price, rate_percent = 10)
  price * (100 + rate_percent) / 100
end
p tax_included(1000)
p tax_included(1000, 8)
p tax_included(199)
```

```text
1100
1080
218
```

`199 * 110 / 100` は `218.9` ですが、整数の割り算なので `218`（切り捨て）になります。端数をどう扱うかは、実務では仕様として決める必要があります。

引数が増えると、どの値が何を意味するのかわからなくなります。`bmi(60.0, 1.7)` では、どちらが体重かわかりません。そこで、**キーワード引数**を使います。

```ruby
def bmi(weight:, height:)
  (weight / (height * height)).round(1)
end
p bmi(weight: 60.0, height: 1.7)
p bmi(height: 1.7, weight: 60.0)
```

```text
20.8
20.8
```

キーワード引数は、呼び出すときに名前を書きます。順番を入れ替えても大丈夫です。`weight:` のように値を書かずに定義すると、**必ず渡す必要がある**引数になります。`tax_percent: 10` のように書けば、デフォルト値付きになります。Rails では、キーワード引数をたくさん使います。

メソッドから複数の値を返したいときは、配列で返し、受け取る側で分けます。

```ruby
def min_max(numbers)
  [numbers.min, numbers.max]
end
low, high = min_max([4, 9, 1])
p low
p high
```

```text
1
9
```

`low, high = 配列` のように書くと、配列の要素が順に変数に入ります。これを**多重代入**と呼びます。

### 引数のエラー

引数の数が合わないと、エラーになります（ファイル名は `r.rb`）。

```ruby
def greet(name)
  "こんにちは、#{name}さん"
end
greet
```

```text
r.rb:1:in `greet': wrong number of arguments (given 0, expected 1) (ArgumentError)
	from r.rb:4:in `<main>'
```

`given 0, expected 1` は「0個渡されたが、1個必要」という意味です。エラーの場所が2行表示されています。1行目は「エラーが起きた場所」（`greet` の定義、1行目）、2行目は「そこを呼び出した場所」（4行目）です。この、呼び出しの道筋を逆にたどった一覧を**バックトレース**と呼びます。原因は、たいてい呼び出した側にあります。バックトレースの読み方は、第7章で詳しく学びます。

キーワード引数を渡し忘れたときも、何が足りないかを教えてくれます（ファイル名は `s.rb`）。

```ruby
def bmi(weight:, height:)
  weight / (height * height)
end
bmi(weight: 60.0)
```

```text
s.rb:1:in `bmi': missing keyword: height (ArgumentError)
	from s.rb:4:in `<main>'
```

（Ruby 3.x では `missing keyword: :height` のように表示されます）

### 名前の習慣：`?` と `!`

Ruby のメソッド名には、`?` や `!` を付けられます。

```ruby
def adult?(age)
  age >= 18
end
p adult?(20)
```

```text
true
```

- `?` で終わるメソッドは、`true` / `false` を返す（真偽を問う）
- `!` で終わるメソッドは、注意が必要な版（多くは元のデータを変える破壊的な版）

これは文法の決まりではなく、Ruby のコミュニティの習慣です。しかし、ほぼすべての Ruby のコードがこの習慣に従っています。自分で作るメソッドでも守ってください。

### スコープ：メソッドの中から外の変数は見えない

ここは少し難しいところです。次のプログラムを `t.rb` として実行してみます。

```ruby
site_name = "My Shop"

def title
  site_name
end

puts title
```

```text
t.rb:4:in `title': undefined local variable or method `site_name' for main:Object (NameError)
	from t.rb:7:in `<main>'
```

メソッドの外で作った変数 `site_name` は、メソッドの中からは見えません。変数が見える範囲を**スコープ**と呼びます。`def` は、新しいスコープを作ります。

なぜ見えないようにしているのでしょうか。メソッドの中から外の変数を自由に読み書きできると、メソッドの動きが「どこで呼ばれたか」に左右されてしまいます。メソッドが使う値は、引数として明示的に受け取る。こうすることで、メソッドを独立した部品として扱えます。上の例は、`def title(site_name)` として、引数で渡せば動きます。

## ブロックを受け取るメソッド

### yield

`each` や `map` には、`{ |s| ... }` のようなブロックを渡してきました。自分で作るメソッドも、ブロックを受け取れます。

```ruby
def twice
  yield
  yield
end

twice { puts "ブロックが呼ばれました" }

def with_border
  puts "-" * 10
  yield
  puts "-" * 10
end

with_border do
  puts "本文"
end
```

```text
ブロックが呼ばれました
ブロックが呼ばれました
----------
本文
----------
```

`yield` と書いた場所で、呼び出し側から渡されたブロックが実行されます。`yield` は英語で「譲る」という意味です。メソッドが「ここはあなたに任せます」と、呼び出し側に処理を譲るイメージです。

`with_border` は、「前後に線を引く」という決まった処理と、「間に何を書くか」という変わる処理を分けています。決まった枠組みはメソッドが持ち、変わる中身はブロックで渡す。これが、ブロックを使う一番の理由です。たとえば「ファイルを開く → 何かする → 必ず閉じる」の「何かする」をブロックで受け取る、といった使い方を第5章で学びます。

### ブロックに値を渡す・ブロックから値を受け取る

`yield` に引数を書くと、ブロックに値を渡せます。そして、ブロックの最後の値が `yield` の戻り値になります。

```ruby
def apply_to(value)
  yield(value)
end
p apply_to(5) { |n| n * 3 }

def maybe_block
  if block_given?
    "ブロックあり: #{yield}"
  else
    "ブロックなし"
  end
end
p maybe_block
p maybe_block { 42 }
```

```text
15
"ブロックなし"
"ブロックあり: 42"
```

`block_given?` は、ブロックが渡されたかどうかを調べます。ブロックなしで `yield` を実行すると、エラーになります。次は、前に定義した `twice` をブロックなしで呼んだ例（ファイル名は `v.rb`）です。

```text
v.rb:2:in `twice': no block given (yield) (LocalJumpError)
	from v.rb:5:in `<main>'
```

### map を自分で作ってみる

`map` がどう動いているのか、自分で作ってみると仕組みが見えてきます。

```ruby
def my_map(array)
  result = []
  array.each do |item|
    result << yield(item)
  end
  result
end
p my_map([1, 2, 3]) { |n| n * 10 }
```

```text
[10, 20, 30]
```

1つずつ要素を取り出してブロックに渡し、ブロックが返した値を集めて返す。`map` の正体は、これだけです。Ruby の便利なメソッドも、中身は今の皆さんに書けるものでできています。これは、この教材全体のテーマである「抽象を降りる」の小さな練習です。演習4-4では、`each` も使わずに作ってみます。

### ブロックは外の変数が見える

`def` の中からは外の変数が見えませんでした。しかし、ブロックの中からは見えます。

```ruby
total = 0
[1, 2, 3].each { |n| total += n }
p total
```

```text
6
```

ブロックは、作られた場所の変数を覚えていて、読み書きできます。このような性質を持つものを**クロージャ**と呼びます。`def` とブロックで、外の変数の見え方が違うことは、混乱しやすいところです。「`def` は壁を作る、ブロックは壁を作らない」と覚えてください。

ブロックは、変数に入れて持ち運ぶこともできます。

```ruby
double = lambda { |n| n * 2 }
p double.call(4)
p [1, 2, 3].map(&double)
square = ->(n) { n * n }
p square.call(5)
```

```text
8
[2, 4, 6]
25
```

`lambda` や `->` で作ったものは、後から `call` で実行できます。`&` を付けると、ブロックとしてメソッドに渡せます。今は「ブロックを値として扱う方法もある」とだけ知っておけば十分です。第14章でルーティングを自作するとき、「この URL ならこの処理」という対応を、こうした値として持つ方法が出てきます。

## 変数は名札：共有と破壊的変更

この章の最後に、とても大事な性質を見ておきます。ここは、経験者でもバグを生みやすいところです。

```ruby
a = "hello"
b = a
b << " world"
p a
p a.equal?(b)
```

```text
"hello world"
true
```

`b` に追記したのに、`a` まで変わっています。なぜでしょうか。

第3章で、変数は「箱」ではなく「名札」だと説明しました。`b = a` は、`a` の中身をコピーして `b` に入れたのではありません。**同じ1つの文字列に、`b` という名札をもう1枚付けた**のです。`equal?` は「同じオブジェクトか」を調べるメソッドで、`true` が返っています。そして `<<` は、文字列そのものを書き換える破壊的なメソッドです。だから、同じ文字列を指している `a` から見ても変わっているのです。

配列でも、メソッドの引数でも同じことが起きます。

```ruby
list = [1, 2, 3]
copy = list
copy << 4
p list

def add_item(items)
  items << "追加"
end
bag = ["本"]
add_item(bag)
p bag
```

```text
[1, 2, 3, 4]
["本", "追加"]
```

メソッドに配列を渡すと、メソッドの中の `items` と外の `bag` は、同じ配列を指します。メソッドの中で破壊的な変更をすると、呼び出し側のデータも変わります。

別のものとして扱いたいときは、`dup` でコピーを作ります。

```ruby
a = "hello world"
c = a.dup
c << "!"
p a
p c
```

```text
"hello world"
"hello world!"
```

非破壊的なメソッドと、破壊的なメソッドの違いも、ここで確かめておきます。

```ruby
name = "taro"
name.upcase
p name
name.upcase!
p name
```

```text
"taro"
"TARO"
```

`upcase` は新しい文字列を返すだけなので、結果を使わなければ何も起きません。`upcase!` は元の文字列を書き換えます。

変更されては困る値は、`freeze` で凍結できます。凍結した値を変更しようとすると、エラーになります。

```console
$ ruby -e 's = "固定".freeze; s << "!"'
-e:1:in `<main>': can't modify frozen String (FrozenError)
```

（Ruby 3.x では、メッセージの後ろに値も表示されます）

まとめると、次の方針が安全です。

- **基本は非破壊的なメソッドを使い、結果を新しい変数に入れる。**
- **引数で受け取った配列や Hash を、メソッドの中で書き換えない。** 必要なら `dup` してから変更する。
- **変更されては困る値は `freeze` する。**

Web アプリでは、1つのデータを複数の場所で使います。どこか1か所の破壊的な変更が、まったく別の画面の表示を変えてしまう、というバグは本当に起きます。

## 実務ではこうなる

Rails のコードを開くと、この章の内容がそのまま並んでいます。

- **`map` / `select` / `find` は毎日使う**：「公開中の記事だけを選び、タイトルの一覧を作る」といった処理は、メソッドチェーンで書くのが普通です。逆に、`each` と空の配列で同じことを書くと、レビューで「`map` で書けますね」と指摘されます。
- **Hash のキーの種類で悩む**：フォームから届くパラメータは文字列のキー、設定はシンボルのキー、というように混在します。Rails には両方を同じように扱える仕組みがありますが、何が起きているかを知らないと、`nil` が返って困ります。
- **`fetch` で早く失敗させる**：設定値など「必ずあるはず」の値は、`fetch` で取り出し、なければすぐエラーにします。
- **メソッドは短く、名前は具体的に**：1つのメソッドが何十行にもなると、読むのもテストするのも難しくなります。「1つのメソッドは1つのことをする」が目安です。
- **ブロックを渡す API が多い**：Rails のテスト、設定、データベースのトランザクションなど、`do ... end` でブロックを渡す書き方がたくさん出てきます。`yield` の仕組みを知っていれば、その裏で何が起きているかを想像できます。

ジュニアがやりがちな失敗も挙げておきます。

- **配列の範囲外や、ないキーで `nil` が返ったことに気付かず、後で `NoMethodError` になる。**
- **整数の平均を `/` で計算して、切り捨てられているのに気付かない。**
- **引数で受け取った配列を `<<` や `sort!` で書き換え、呼び出し側のデータを壊す。**
- **`each` の戻り値を使おうとする。** `each` は変換結果ではなく、元の配列を返します。

## 演習

演習のファイルは `~/workspace/ch04/` に作ります。各演習が終わったらコミットしてください。データはすべて例のとおりの架空のものを使います。

### 演習4-1：1週間の気温

- `temperature.rb` を作り、次の配列を使って、最高・最低・平均（小数第1位まで）・25度を超えた日数を表示してください。
  ```ruby
  temps = [22, 25, 27, 19, 30, 28, 24]
  ```
- 出力の形は次のとおりです。
  ```text
  最高: 30度
  最低: 19度
  平均: 25.0度
  25度を超えた日: 3日
  ```
- **完了条件**：`ruby temperature.rb` の出力が、上の4行と完全に一致する。`each` や `while` を使わずに書けている。
- ヒント：配列には、最大・最小・合計・条件に合う数を求めるメソッドがあります。平均は、整数の割り算の切り捨てに注意してください。`round(1)` で小数第1位に丸められます。

### 演習4-2：単語の出現回数

- `word_count.rb` を作り、標準入力から読んだ文章に含まれる単語の出現回数を数え、多い順に上位3つを `単語: 回数` の形で表示してください。
  - 単語は空白で区切られているものとし、大文字・小文字は区別しない（すべて小文字として数える）
  - 回数が同じ単語は、アルファベット順に並べる
- **完了条件**：次のコマンドの出力が、下の3行と一致する。
  ```console
  echo "The cat and the dog and THE bird" | ruby word_count.rb
  ```
  ```text
  the: 3
  and: 2
  bird: 1
  ```
- ヒント：入力全体は `$stdin.read` で読めます。数えるには `Hash.new(0)` が使えます。「回数の多い順、同じならアルファベット順」は、`sort_by` のブロックで `[回数を負にしたもの, 単語]` のような配列を返すと実現できます。配列どうしは、先頭の要素から順に比べられます。

### 演習4-3：成績を集計するメソッド

- `report.rb` を作り、次のデータを使います。
  ```ruby
  STUDENTS = [
    { name: "Aoi", score: 82, club: "soccer" },
    { name: "Ken", score: 67, club: "music" },
    { name: "Mio", score: 91, club: "soccer" },
    { name: "Ren", score: 74, club: "music" },
    { name: "Sora", score: 58, club: "art" },
  ]
  ```
- 次の3つのメソッドを定義してください。どのメソッドも、生徒の配列を**引数で受け取り**、受け取った配列を書き換えないこと。
  - `average_score(students)`：平均点を小数第1位まで丸めて返す
  - `passed_names(students, border: 60)`：`border` 点以上の人の名前の配列を返す
  - `club_summary(students)`：部活ごとの「人数」と「平均点」を表す文字列の配列を返す
- これらを使って、次のように表示してください。
  ```text
  平均点: 74.4
  合格者: Aoi, Ken, Mio, Ren
  70点以上: Aoi, Mio, Ren
  soccer: 2人 平均86.5点
  music: 2人 平均70.5点
  art: 1人 平均58.0点
  ```
- **完了条件**：`ruby report.rb` の出力が、上の6行と一致する。メソッドの中で `STUDENTS` を直接参照していない（`grep -n STUDENTS report.rb` で、定義と、メソッドを呼び出す行にしか出てこない）。
- ヒント：`group_by` を使うと、部活ごとの配列を作れます。1つのメソッドが長くなったら、平均を求める部分を別のメソッドにできないか考えてください。

### 演習4-4：イテレータを自作する

- `my_iterators.rb` を作り、次の4つのメソッドを定義してください。**中では `each`・`map`・`select`・`count`・`times` などのブロックを使うメソッドを使わず**、`while` と `yield` だけで書きます。
  - `my_each(array)`：各要素をブロックに渡す。戻り値は受け取った配列
  - `my_map(array)`：ブロックの結果を集めた新しい配列を返す
  - `my_select(array)`：ブロックが真になった要素の配列を返す
  - `my_count(array)`：ブロックが真になった数を返す。ブロックがなければ要素の数を返す
- ファイルの最後に、次の確認用のコードを書いてください。
  ```ruby
  my_each([1, 2]) { |n| puts n }
  p my_map([1, 2, 3]) { |n| n * 10 }
  p my_select([1, 2, 3, 4]) { |n| n.even? }
  p my_count([1, 2, 3, 4]) { |n| n > 1 }
  p my_count([1, 2, 3, 4])
  ```
- **完了条件**：`ruby my_iterators.rb` の出力が次の6行と一致する。
  ```text
  1
  2
  [10, 20, 30]
  [2, 4]
  3
  4
  ```
- ヒント：配列の要素は、インデックス（`array[i]`）で取り出せます。`i` を 0 から増やしていき、`array.length` に達したら終わります。ブロックがあるかどうかは `block_given?` で調べられます。

### 演習4-5（発展）：買い物かごの合計

- `cart.rb` を作り、次のメソッドを定義してください。
  ```ruby
  def cart_total(items, tax_percent: 10, coupon: 0)
    # ここを自分で書く
  end
  ```
  - `items` は `{ name: "ノート", price: 300, qty: 2 }` のような Hash の配列
  - 小計（単価×数量の合計）からクーポンの金額を引き、その後に税を足す
  - 税の端数は切り捨て。クーポンを引いて 0 円未満になる場合は 0 円とする
  - 計算はすべて整数で行い、小数（Float）を使わない
- 次のデータで確かめてください。
  ```ruby
  items = [
    { name: "ノート", price: 300, qty: 2 },
    { name: "ペン", price: 120, qty: 3 },
  ]
  ```
- **完了条件**：次の結果になる。
  | 呼び出し | 結果 |
  |---|---|
  | `cart_total(items)` | `1056` |
  | `cart_total(items, coupon: 100)` | `946` |
  | `cart_total(items, tax_percent: 8)` | `1036` |
  | `cart_total(items, coupon: 5000)` | `0` |
  | `cart_total([])` | `0` |
  さらに、`grep -n "\.to_f\|fdiv\|[0-9]\.[0-9]" cart.rb` で何も表示されない（小数を使っていない）。
- ヒント：小計を求める部分は、それだけで1つのメソッドにすると読みやすくなります。「0 円未満なら 0」は、`if` でも、`[値, 0].max` のような書き方でも表せます。

## 確認クイズ

**Q1.** `nums = [10, 20, 30]` のとき、`nums[3]` と `nums[-1]` はそれぞれ何を返しますか。

**Q2.** `[1, 2, 3].each { |n| n * 2 }` と `[1, 2, 3].map { |n| n * 2 }` の戻り値はそれぞれ何ですか。

**Q3.** `h = { "id" => 1 }` のとき、`h[:id]` は何を返しますか。なぜですか。

**Q4.** 次のプログラムを実行すると、`original` はどうなりますか。理由も説明してください。
```ruby
def add_tax_label(list)
  list << "税込"
end
original = ["本"]
add_tax_label(original)
```

**Q5.** `def` の中からは外の変数が見えないのに、ブロックの中からは見えます。この違いがあると、どんなときにうれしいですか。

### 解答と解説

**A1.** `nums[3]` は `nil`、`nums[-1]` は `30` です。インデックスは 0 から数えるので、3 は4番目で、存在しません。存在しない場合はエラーではなく `nil` が返ります。マイナスは後ろから数えます。

**A2.** `each` は元の配列 `[1, 2, 3]` を返します。`map` はブロックの結果を集めた `[2, 4, 6]` を返します。`each` は処理をすることが目的で、変換した結果は返しません。

**A3.** `nil` を返します。`"id"`（文字列）と `:id`（シンボル）は別のキーだからです。エラーにならないので、気付きにくいバグになります。

**A4.** `original` は `["本", "税込"]` に変わります。メソッドの引数 `list` と、外の `original` は同じ配列を指していて、`<<` はその配列そのものを書き換えるからです。元の配列を変えたくなければ、`list + ["税込"]` のように新しい配列を作って返すか、`dup` してから変更します。

**A5.** `def` が壁を作ることで、メソッドは引数だけに頼る独立した部品になり、どこから呼んでも同じように動きます。一方、ブロックが外の変数を見られると、`each` の中で外の `total` に足し込むような、その場の処理を短く書けます。メソッドは「再利用する部品」、ブロックは「その場で渡す処理」という役割の違いに合っています。

## AIの使い方（この章）

この章では、AI を「メソッドの選び方の相談相手」「自分のコードのレビュアー」として使います。

推奨する聞き方の例：

- 「Ruby の配列で、『条件に合う要素を探す』メソッドには `find`・`select`・`any?`・`include?` などがあります。それぞれ何を返すかの違いを、表で説明してください」
- 「演習で `each` と空の配列を使って次のコードを書きました（自分のコードを貼る）。正しく動きます。Ruby らしい書き方にするには、どのメソッドを使うと考えればよいですか。答えのコードではなく、使うべきメソッドの名前と理由だけ教えてください」
- 「`yield` の動きについて、私の理解を説明します（自分の説明を書く）。間違っている点や、足りない点を指摘してください」

この章でやってはいけない使い方：

- **演習4-4（イテレータの自作）の答えを AI に書かせる。** この演習は、`map` や `select` の中身を自分の手で組み立てて理解するためのものです。答えを見てしまうと、仕組みを理解する機会がなくなります。
- **AI の書いたメソッドチェーンを、各段階の値を確かめずにそのまま使う。** 長いチェーンは、途中で何が起きているかが見えにくくなります。自分で `p` を挟んで、1段ずつ値を確かめてください。

## まとめ

- 配列は順番で、Hash はキーで値を取り出します。範囲外の番号やないキーは `nil` を返すので、必要なら `fetch` で早く失敗させます。
- `each` / `map` / `select` / `find` / `sum` / `group_by` などを目的に応じて使い分けると、ループを書かずに短く読みやすく書けます。
- メソッドは `def` で定義し、最後の式が戻り値になります。キーワード引数を使うと、呼び出し側が読みやすくなります。
- `yield` で呼び出し側のブロックを実行でき、`def` は壁を作るがブロックは外の変数が見えます。
- 変数は名札なので、破壊的な変更は同じオブジェクトを指すすべての場所に影響します。

## 用語

| 用語 | 意味 |
|---|---|
| コレクション | 複数の値をまとめて入れる入れ物。配列や Hash |
| 配列（Array） | 値を順番に並べた入れ物。`[1, 2, 3]` |
| インデックス | 配列の要素の番号。0 から数える |
| Hash | キーと値の組を入れる入れ物。`{ name: "Taro" }` |
| キー / シンボル | Hash で値を取り出すための名前 / `:name` のような名前を表す値 |
| 破壊的メソッド | 元のオブジェクトそのものを書き換えるメソッド。多くは `!` が付く |
| メソッドチェーン | メソッドを `.` でつなげて、順にデータを加工する書き方 |
| 引数 / 戻り値 | メソッドに渡す値 / メソッドが返す値 |
| デフォルト値 | 引数を省略したときに使われる値 |
| キーワード引数 | `weight: 60` のように名前を付けて渡す引数 |
| ガード節 | おかしな場合を先に `return` で処理する書き方 |
| スコープ | 変数が見える範囲。`def` は新しいスコープを作る |
| yield | メソッドに渡されたブロックを実行する命令 |
| クロージャ | 作られた場所の変数を覚えていて使える処理のまとまり |
| バックトレース | エラーが起きるまでの呼び出しの道筋の一覧 |
