# 第3章 Ruby入門1：値・変数・条件分岐・繰り返し

> **この章のゴール**：Ruby のプログラムを書いて実行し、値・変数・条件分岐・繰り返しを組み合わせた小さなスクリプトを自力で作れる。
> **目安時間**：読む 2.5時間 ＋ 演習 4時間
> **前提**：第2章まで

## この章で学ぶこと

- Ruby のプログラムをファイルに書いて実行でき、`irb` で1行ずつ試せる
- `puts` と `p` の違いを説明し、目的に応じて使い分けられる
- 整数・小数・文字列・真偽値・`nil` を区別し、型の変換ができる
- 変数に値を入れて使い、式展開で文字列に埋め込める
- `if` / `case` で条件分岐を書き、「偽になるのは `false` と `nil` だけ」を説明できる
- `times` / `each` / `while` などで繰り返しを書き、`gets` と `ARGV` で入力を受け取れる

## プログラムを書いて動かす

### 最初のプログラム

`~/workspace/ch03` を作り、VS Code で開きます。

```console
mkdir -p ~/workspace/ch03
cd ~/workspace/ch03
code .
```

VS Code で `hello.rb` というファイルを作り、次の2行を書いて保存します。

```ruby
puts "こんにちは、Ruby"
puts 1 + 2
```

ターミナルで実行します。

```console
$ ruby hello.rb
こんにちは、Ruby
3
```

`ruby ファイル名` で、Ruby がファイルを上から1行ずつ読んで実行します。これが Ruby のプログラムの基本の動かし方です。`.rb` は Ruby のプログラムを表す拡張子です。

**プログラミング言語**とは、コンピュータへの指示を、人間にも読み書きしやすい形で書くための言葉です。Ruby は、日本のまつもとゆきひろさんが作った言語で、「書いていて楽しい」ことを大事にしています。Web 開発のフレームワーク Rails の言語として、多くの会社で使われています。

### irb：1行ずつ試す

ちょっとした動きを確かめたいときは、**irb**（Interactive Ruby）を使います。打った式をすぐに実行して、結果を見せてくれます。

```console
$ irb
irb(main):001:0> 1 + 2
=> 3
irb(main):002:0> name = "Ruby"
=> "Ruby"
irb(main):003:0> name.length
=> 4
irb(main):004:0> exit
```

`=>` の後ろが、その式の結果です（Ruby 3.3 以降ではプロンプトが `irb(main):001>` のように少し短くなります）。irb は電卓のように使える実験場です。「これはどうなるんだろう」と思ったら、すぐ irb で試す習慣を付けてください。終了するときは `exit` と打ちます。

ファイルに書くか irb で試すかは、次のように使い分けます。

- **irb**：1〜数行の動きを確かめる。消えてもよい実験
- **ファイル**：何行もあるプログラム、何度も実行するもの、残しておきたいもの

### コメント

`#` から行末までは**コメント**です。Ruby は無視します。人間向けのメモとして使います。

```ruby
# 合計金額を表示する
puts 100 + 200 # 税抜きの合計
```

コメントには「何をしているか」より「なぜそうしているか」を書くのがよいとされます。何をしているかは、コードを読めばわかるからです。

## 画面に出す：puts と p

値を画面に出す方法は、主に3つあります。

```ruby
puts "こんにちは"
puts 3
p "こんにちは"
p 3
print "改行なし"
print "です\n"
puts nil
p nil
```

```text
こんにちは
3
"こんにちは"
3
改行なしです

nil
```

- **`puts`**：値を、人間に読みやすい形で表示し、最後に改行します。文字列は `"` なしで出ます。`nil`（何もない、を表す値。後で説明します）は空行になります。
- **`p`**：値を、**プログラマが確かめやすい形**で表示します。文字列は `"` 付きで出るので、文字列なのか数なのかが区別できます。`nil` も `nil` と表示されます。
- **`print`**：`puts` と似ていますが、最後に改行しません。`\n` は改行を表す記号です。

使い分けの目安は、「利用者に見せる出力は `puts`、自分が中身を確かめるときは `p`」です。たとえば、`"3"`（文字の3）と `3`（数の3）は、`puts` ではどちらも `3` と表示されて区別できません。`p` なら `"3"` と `3` で区別できます。プログラムが思いどおりに動かないとき、`p` で途中の値を確かめるのは、プロも毎日使う基本のデバッグ方法です（第7章）。

## 値と型

### 値には種類がある

プログラムで扱うデータを**値**と呼びます。値には**型**（種類）があります。`.class` を付けると、値の型を調べられます。

```ruby
p 10.class
p 3.14.class
p "abc".class
p :name.class
p true.class
p nil.class
p((1..3).class)
```

```text
Integer
Float
String
Symbol
TrueClass
NilClass
Range
```

| 型 | 例 | 意味 |
|---|---|---|
| Integer（整数） | `10`、`-3`、`1_000_000` | 小数点のない数。`_` は読みやすくするための区切りで、無視される |
| Float（浮動小数点数） | `3.14`、`2.0` | 小数点のある数 |
| String（文字列） | `"abc"`、`'abc'` | 文字の並び |
| Symbol（シンボル） | `:name` | 名前を表す軽い値。第4章の Hash でよく使う |
| true / false（真偽値） | `true`、`false` | 正しい / 正しくない |
| nil | `nil` | 「何もない」ことを表す特別な値 |
| Range（範囲） | `1..3`、`1...3` | 範囲。`..` は終わりを含み、`...` は含まない |

Ruby では、**すべての値がオブジェクト**です。オブジェクトとは、データと、そのデータに対してできる操作（**メソッド**）をひとまとめにしたものです。`"ruby".upcase` の `upcase` がメソッドで、「大文字にする」という操作です。値の後ろに `.メソッド名` と書いて呼び出します。オブジェクトとクラスの詳しい話は、第5章で扱います。

### 数の計算

```ruby
p 7 / 2
p 7 % 2
p 7.0 / 2
p 2 ** 10
p 7.fdiv(2)
p 0.1 + 0.2
```

```text
3
1
3.5
1024
3.5
0.30000000000000004
```

ここには、初心者がつまずく点が2つあります。

**1つ目：整数どうしの割り算は、小数点以下が切り捨てられます。** `7 / 2` は `3.5` ではなく `3` です。整数どうしの計算結果は整数になる、という決まりだからです。小数の結果がほしいときは、どちらかを小数にする（`7.0 / 2`）か、`fdiv` を使います。`%` は割り算の余りです。

**2つ目：小数の計算には、ごくわずかな誤差が出ます。** `0.1 + 0.2` が `0.3` になりません。コンピュータは内部で数を2進数で表しており、`0.1` をぴったり表せないからです。これは Ruby に限らず、ほとんどの言語で起きます。そのため、**お金の計算に小数（Float）を使ってはいけません**。円なら整数で計算する、のが実務の鉄則です。

演算の優先順位は、算数と同じです。`1 + 2 * 3` は `7`、`(1 + 2) * 3` は `9` です。迷ったら括弧を付けてください。読む人にも親切です。

### 文字列

文字列は `"`（ダブルクォート）か `'`（シングルクォート）で囲みます。2つには大事な違いがあります。

```ruby
name = "Taro"
age = 20
puts "名前は#{name}、年齢は#{age}歳です"
puts '名前は#{name}です'
puts "合計: #{1 + 2}"
puts "1行目\n2行目"
puts '1行目\n2行目'
```

```text
名前はTaro、年齢は20歳です
名前は#{name}です
合計: 3
1行目
2行目
1行目\n2行目
```

ダブルクォートの中では、`#{ }` の中に書いた式が評価され、結果が埋め込まれます。これを**式展開**と呼びます。`\n`（改行）のような特別な記号も働きます。シングルクォートの中では、どちらも働かず、書いたとおりの文字になります。

迷ったらダブルクォートを使ってください。式展開が必要になったときに書き直さずに済みます。

文字列には、便利なメソッドがたくさんあります。

```ruby
p "Ruby".length
p "ruby".upcase
p "Hello World".downcase
p "  space  ".strip
p "abc".reverse
p "hello".include?("ell")
p "a,b,c".split(",")
p "ab" * 3
p "Hello" + " " + "World"
```

```text
4
"RUBY"
"hello world"
"space"
"cba"
true
["a", "b", "c"]
"ababab"
"Hello World"
```

`strip` は前後の空白を取り除きます。フォームに入力された値を扱うときによく使います。`include?` のように `?` で終わるメソッドは、`true` か `false` を返すのが Ruby の習慣です。`split` の結果の `[...]` は**配列**で、第4章で学びます。

すべてのメソッドを覚える必要はありません。「こういうことができるメソッドがあるはず」と思ったら、Ruby の公式リファレンス（<https://docs.ruby-lang.org/ja/>）で `String` のページを調べてください。調べ方は第7章で詳しく扱います。

### 型の変換

型が違う値どうしは、そのままでは組み合わせられないことがあります。次の2行を `e.rb` に書いて実行してみます。

```ruby
age = 20
puts "年齢: " + age
```

```text
e.rb:2:in `+': no implicit conversion of Integer into String (TypeError)
	from e.rb:2:in `<main>'
```

これは**エラー**です。プログラムがそこで止まり、理由が表示されます。英語ですが、落ち着いて読みましょう。

- `e.rb:2`：`e.rb` の2行目で起きた
- `` `+' ``：`+` の処理の中で起きた
- `no implicit conversion of Integer into String`：Integer（整数）を String（文字列）に自動では変換しない
- `(TypeError)`：エラーの種類。型（Type）が合わないエラー

文字列と整数を `+` でつなごうとしたのが原因です。Ruby は、勝手に型を変換しません。意図しない変換による間違いを防ぐためです。直すには、式展開（`"年齢: #{age}"`）を使うか、`age.to_s` で文字列に変換します。

型を変換するメソッドは次のとおりです。

```ruby
p "42".to_i
p "42abc".to_i
p "abc".to_i
p 42.to_s
p "3.5".to_f
p 10.to_f
p Integer("42")
```

```text
42
42
0
"42"
3.5
10.0
42
```

`to_i` は「整数にする」メソッドです。ただし、数として読めない文字列は `0` になり、エラーになりません。これは便利な反面、危険でもあります。利用者が `abc` と入力したのか `0` と入力したのか、区別できないからです。

厳しくチェックしたいときは `Integer("文字列")` を使います。数として読めなければエラーにしてくれます。

```console
$ ruby -e 'Integer("abc")'
-e:1:in `Integer': invalid value for Integer(): "abc" (ArgumentError)
	from -e:1:in `<main>'
```

`ruby -e '...'` は、ファイルを作らずに、その場で1行のプログラムを実行する方法です。

外から入ってきた値（利用者の入力など）は、**常に疑ってかかる**のが基本です。これは後の章で学ぶ Web アプリの安全対策にも直結する考え方です。

なお、エラーの文言や記号（`` ` `` と `'` など）は、Ruby の版によって少し違います。このページの例は Ruby 2.6 で実行したもので、3.3 以降では見た目が少し変わります。しかし、「ファイル名:行番号」「何が起きたか」「エラーの種類」という読み方は同じです。

## 変数と定数

### 変数

**変数**は、値に付ける名札です。`=` で名札を付けます。これを**代入**と呼びます。

```ruby
price = 100
price = price + 50
price += 30
p price
```

```text
180
```

`=` は数学の「等しい」ではなく、「右の値に、左の名前を付ける」という意味です。2行目は「今の `price`（100）に 50 を足した値に、改めて `price` という名前を付ける」です。`price += 30` は `price = price + 30` の省略形です。

箱にたとえる説明もよくありますが、Ruby では「名札」のほうが正確です。値そのものは別の場所にあり、変数はそれを指しているだけです。この違いは第4章で大事になります。

変数名の付け方には習慣があります。

- 小文字とアンダースコアで書く（**スネークケース**）：`total_price`、`user_name`
- 中身がわかる名前にする：`x` や `a` より `tax_rate`
- 数字で始めない、Ruby が使う単語（`if`、`end`、`class` など）は使わない

名前の付け方は、読みやすさを大きく左右します。プログラムは書く時間より読む時間のほうがずっと長いので、良い名前を考えることに時間を使ってください。

### 定数

大文字で始まる名前は**定数**です。変えるつもりのない値に使います。次のプログラムを `const.rb` として実行してみます。

```ruby
TAX_RATE = 0.1
TAX_RATE = 0.08
p TAX_RATE
```

```text
const.rb:2: warning: already initialized constant TAX_RATE
const.rb:1: warning: previous definition of TAX_RATE was here
0.08
```

Ruby の定数は、実は再代入できてしまいます。ただし、**警告**（warning）が出ます。警告はエラーとは違い、プログラムは止まりません。しかし「たぶん間違っていますよ」という合図なので、無視してはいけません。

## 条件分岐

### if

条件によって処理を変えるには、`if` を使います。

```ruby
score = 72

if score >= 80
  puts "よくできました"
elsif score >= 60
  puts "合格です"
else
  puts "もう少し"
end
```

```text
合格です
```

上から順に条件を調べ、最初に当てはまったところだけを実行します。`elsif`（else if の略。`elseif` ではないので注意）と `else` は省略できます。最後の `end` は省略できません。

`if` の中の行は、半角スペース2つ分ずらして書きます。これを**インデント**と呼びます。Ruby はインデントがなくても動きますが、どこからどこまでが `if` の中かが見えなくなります。Ruby では2スペースが標準です。

### 比較と論理の演算子

```ruby
p 5 > 3
p 5 == 5.0
p "a" == "A"
p 5 != 3
p(72 >= 60 && 72 < 80)
p !true
```

```text
true
true
false
true
true
false
```

| 演算子 | 意味 |
|---|---|
| `==` | 等しい（`=` 1つは代入なので注意） |
| `!=` | 等しくない |
| `>`、`<`、`>=`、`<=` | 大小の比較 |
| `&&` | かつ（両方が真なら真） |
| `\|\|` | または（どちらかが真なら真） |
| `!` | 否定（真と偽を反転） |

`==` と `=` を間違えるのは、誰もが一度はやる失敗です。`if score = 80` と書くと、比較ではなく代入になり、思わぬ動きをします（Ruby は警告を出してくれます）。

### 真と偽：Ruby で「偽」になるのは2つだけ

ここは、他の言語の経験がある人ほどつまずくところです。

**Ruby で偽として扱われるのは、`false` と `nil` の2つだけです。それ以外は、すべて真です。** `0` も、空の文字列 `""` も真です。

```ruby
zero = 0
empty = ""
puts "0は真として扱われる" if zero
puts "空文字も真として扱われる" if empty
puts "nilは偽として扱われる" unless nil
```

```text
0は真として扱われる
空文字も真として扱われる
nilは偽として扱われる
```

この例では、`if` を文の後ろに書く形（**後置 if**）を使っています。処理が1行で済むときに便利です。`unless` は `if` の反対で、「〜でなければ」という意味です。

なぜこれが大事なのでしょうか。Web アプリでは、「値が入力されたか」を確かめる場面がよくあります。入力欄が空のとき、値は `""`（空文字）で届くことがあります。`if name` と書くと、空文字でも真になり、「入力あり」と判断してしまいます。空かどうかを調べるには `name.empty?` のように、はっきり書く必要があります。

### 三項演算子

条件によって値を選ぶだけなら、1行で書けます。

```ruby
label = score >= 60 ? "合格" : "不合格"
puts label
```

```text
合格
```

`条件 ? 真のときの値 : 偽のときの値` という形です。短く書けますが、入れ子にすると読みにくくなります。複雑なら `if` を使ってください。

### case

1つの値をいくつもの候補と比べるときは、`case` が読みやすくなります。

```ruby
command = "stop"
case command
when "start"
  puts "開始します"
when "stop", "quit"
  puts "終了します"
else
  puts "不明なコマンドです"
end
```

```text
終了します
```

`when` には、カンマで区切って複数の候補を書けます。範囲（Range）も使えます。

```ruby
month = 4
season = case month
         when 3..5 then "春"
         when 6..8 then "夏"
         when 9..11 then "秋"
         else "冬"
         end
puts season
```

```text
春
```

この例では、`case` 全体の結果を変数 `season` に入れています。Ruby では、`if` や `case` も**値を返す式**です。最後に評価された値が、全体の値になります。この性質は、第4章のメソッドで大事になります。

`case` の `when` は、後の章でルーティング（URL によって処理を振り分ける仕組み）を自作するときにも使えます。「入力によって処理を振り分ける」のは、Web サーバの中心的な仕事です。

## 繰り返し

### times・upto・each

同じ処理を何回も行うには、繰り返しを使います。Ruby では、回数や範囲に「繰り返して」と頼む書き方が中心です。

```ruby
3.times do |i|
  puts "#{i}回目"
end

1.upto(3) { |n| puts n * 10 }
```

```text
0回目
1回目
2回目
10
20
30
```

`3.times` は「3回繰り返す」です。`do` と `end` の間が、繰り返す処理です。`|i|` は、何回目かを受け取る変数です。**0 から数える**ことに注意してください。プログラミングでは、0 から数えるのが一般的です。

`do ... end` と `{ ... }` は、どちらも同じ「繰り返す処理のまとまり」を表します。このまとまりを**ブロック**と呼びます。習慣として、1行なら `{ }`、複数行なら `do ... end` を使います。ブロックは Ruby の最も大事な仕組みの1つで、第4章で詳しく学びます。

範囲（Range）の `each` もよく使います。

```ruby
(1..5).each do |n|
  next if n == 2
  break if n == 4
  puts n
end
```

```text
1
3
```

- `next`：今回の残りの処理を飛ばして、次の繰り返しに進む
- `break`：繰り返し全体をやめる

`n` が 2 のときは `next` で飛ばし、4 になったところで `break` で終わります。

範囲には `..` と `...` の2つの書き方があります。

```ruby
p((1...5).to_a)
p((1..5).to_a)
```

```text
[1, 2, 3, 4]
[1, 2, 3, 4, 5]
```

`...`（点3つ）は終わりの値を含みません。点の数と含む範囲が逆に感じられて、間違えやすいところです。

### while・until・loop

条件が成り立つ間、繰り返すには `while` を使います。

```ruby
count = 0
while count < 3
  count += 1
  puts "count = #{count}"
end
```

```text
count = 1
count = 2
count = 3
```

`until` は `while` の反対で、「条件が成り立つまで」繰り返します。`loop do ... end` は、`break` するまで永遠に繰り返します。

```ruby
i = 0
loop do
  i += 1
  break if i > 2
  puts "loop #{i}"
end
```

```text
loop 1
loop 2
```

`while` や `loop` では、**終わる条件を書き忘れると、永遠に止まりません**。これを**無限ループ**と呼びます。プログラムが止まらなくなったら、慌てずに `Ctrl-C` を押してください（第1章）。上の例で `i += 1` を書き忘れると、無限ループになります。

回数や範囲が決まっているなら `times` や `each` を使い、`while` は「いつ終わるか事前にわからない」ときに使うのが Ruby らしい書き方です。後の章で作る Web サーバは、「接続が来るのを待ち、来たら処理する」を、`loop` で繰り返します。

## 入力を受け取る

### gets：キーボードから読む

`gets` は、キーボードから1行読み込みます。次の3行を `greet.rb` として保存します。

```ruby
print "お名前は？ "
name = gets.chomp
puts "こんにちは、#{name}さん"
```

```console
$ ruby greet.rb
お名前は？ 花子
こんにちは、花子さん
```

`gets` で読んだ文字列の末尾には、Enter キーの改行 `\n` が付いています。`chomp` は、その末尾の改行を取り除くメソッドです。

```ruby
line = gets
p line
p line.chomp
```

`hello` と入力した場合の出力です。

```text
"hello\n"
"hello"
```

`p` を使うと、改行が付いていることがはっきり見えます。`chomp` を忘れると、`"花子\n"` と比較しても `"花子"` と一致しない、という不思議なバグになります。

`gets` で読んだ値は、**いつも文字列**です。数として使うなら `to_i` などで変換します。

### ARGV：コマンドの引数を受け取る

`ruby ファイル名` の後ろに書いた引数は、`ARGV` で受け取れます。次のプログラムを `args.rb` として保存します。

```ruby
p ARGV
first = ARGV[0]
puts "最初の引数は #{first} です"
```

```console
$ ruby args.rb apple 42
["apple", "42"]
最初の引数は apple です
```

`ARGV[0]` が1つ目、`ARGV[1]` が2つ目の引数です（0 から数えます）。`42` も文字列として届くことに注意してください。

### gets と ARGV の落とし穴

ここは少し難しい話です。`gets` を使うプログラムに引数を渡すと、エラーになることがあります。

```console
$ ruby greet.rb hoge
お名前は？ greet.rb:2:in `gets': No such file or directory @ rb_sysopen - hoge (Errno::ENOENT)
	from greet.rb:2:in `gets'
	from greet.rb:2:in `<main>'
```

実は `gets` は、引数があると「それはファイル名だ」と解釈して、そのファイルから読もうとします。`hoge` というファイルはないので、エラーになります。キーボードから確実に読みたいときは、`$stdin.gets` と書きます。`$stdin` は「標準入力」、つまり普段はキーボードを表します。演習3-4で、この知識を使います。

### パイプで入力を渡す

第1章で学んだパイプを使うと、キーボードの代わりに、別のコマンドの出力を入力として渡せます。

```console
$ echo "花子" | ruby greet.rb
お名前は？ こんにちは、花子さん
```

入力を毎回手で打たなくて済むので、プログラムの動作確認が楽になります。これは第6章で学ぶ「テストの自動化」の考え方の入口です。

## エラーを怖がらない

最後に、よく出るエラーをまとめて見ておきます。エラーは「怒られている」のではなく、「ここがおかしいよ」という親切な案内です。

**NameError**：知らない名前が使われた（ファイル名は `f.rb`）

```ruby
mesage = "hi"
puts message
```

```text
f.rb:2:in `<main>': undefined local variable or method `message' for main:Object (NameError)
Did you mean?  mesage
```

1行目で `mesage`（綴り間違い）に代入し、2行目で `message` を使っています。`Did you mean?  mesage` と、似た名前を教えてくれています。

**NoMethodError**：その値には、そのメソッドがない（ファイル名は `g.rb`）

```ruby
name = nil
puts name.upcase
```

```text
g.rb:2:in `<main>': undefined method `upcase' for nil:NilClass (NoMethodError)
Did you mean?  case
```

`nil` に `upcase` はありません。`Did you mean?  case` という提案は、ここでは的外れです。提案は綴りの似た名前を挙げているだけなので、参考程度に読みます。「`nil` に対してメソッドを呼んだ」というエラーは、実務で最もよく見るエラーの1つです。「あるはずの値が、実は `nil` だった」ことが原因です。どこで `nil` になったかを、`p` でさかのぼって探します。

**SyntaxError**：文法が間違っている（ファイル名は `h.rb`）

```ruby
if true
  puts "ok"
```

```text
h.rb:2: syntax error, unexpected end-of-input, expecting end
```

`end` を書き忘れています。「ファイルの終わり（end-of-input）に来たが、`end` が来るはずだった」という意味です。文法エラーは、プログラムを実行する前に見つかります。インデントをそろえておくと、`end` の書き忘れに気付きやすくなります。

エラーメッセージを読むときの順番は、いつも同じです。

1. **どのファイルの何行目か**を見る
2. **エラーの種類**（`NameError` など）を見る
3. **メッセージ**を読む。わからない単語は調べる
4. その行と、その少し前の行を見る

エラーの読み方とデバッグは、第7章でさらに詳しく学びます。

## 実務ではこうなる

この章の内容は、Rails の現場でも毎日使います。いくつか例を挙げます。

- **`nil` との戦い**：`undefined method ... for nil` は、現場で最もよく見るエラーです。データベースに値が入っていない、フォームが空で送られた、などが原因です。「この値は `nil` になりうるか」を常に考える癖を付けてください。
- **入力は文字列で届く**：Web のフォームから届く値は、すべて文字列です。数として扱うなら変換が必要で、変換できない値が来たときの扱いも決めておく必要があります。`to_i` が黙って `0` を返す性質は、バグの原因になりやすいところです。
- **お金に Float を使わない**：金額の計算で小数の誤差が出ると、請求額が1円ずれる、といった事故になります。整数で計算するか、誤差の出ない専用の型を使います。
- **`p` と `puts` でのデバッグ**：現場でも、「とりあえず `p` で値を見る」は基本の調査方法です。ただし、確認が終わったら消し忘れないようにします。コミット前の `git diff --staged` で見つけられます。
- **コードの見た目をそろえる**：現場では、RuboCop などの道具で、インデントや書き方を自動でチェックすることが多いです。チームのルールに合わせて書くのも仕事のうちです。

ジュニアがやりがちな失敗も挙げておきます。

- **`0` や `""` が偽だと思い込んで条件を書く。**
- **`gets` の `chomp` を忘れ、比較がいつも失敗する。**
- **エラーメッセージを読まずに、コードをあちこち書き換える。** まず行番号とエラーの種類を見てください。
- **`while` で終了条件を書き忘れ、無限ループになる。**

## 演習

演習のファイルは `~/workspace/ch03/` に作ります。完成コードは載せていません。自分で考えて書くことが、この章の目的です。各演習が終わったら、コミットしてください。

### 演習3-1：自己紹介と計算

- `intro.rb` を作り、変数 `name`（名前、ハンドルネームでよい）、`birth_year`（生まれた年、架空の値でよい）、`current_year`（`2026`）を定義してください。
- 次の3行を表示してください。年齢は、変数を使って計算します。
  ```text
  名前: Taro
  年齢: 26歳（2026年時点）
  10年後: 36歳
  ```
- **完了条件**：`ruby intro.rb` の出力が、上と同じ形の3行になる（名前と数は自分の値でよい）。`birth_year` の値だけを変えて再実行すると、2行目と3行目の数が正しく変わる。
- ヒント：式展開 `#{ }` の中には、`current_year - birth_year` のような式も書けます。

### 演習3-2：FizzBuzz

- `fizzbuzz.rb` を作り、1 から 30 までの数を1行ずつ表示してください。ただし、3 の倍数のときは数の代わりに `Fizz`、5 の倍数のときは `Buzz`、3 と 5 の両方の倍数のときは `FizzBuzz` と表示します。
- **完了条件**：次の4つのコマンドの結果が、それぞれ右のとおりになる。
  - `ruby fizzbuzz.rb | wc -l` → `30`
  - `ruby fizzbuzz.rb | sed -n 15p` → `FizzBuzz`
  - `ruby fizzbuzz.rb | grep -c Fizz` → `10`
  - `ruby fizzbuzz.rb | grep -c Buzz` → `6`
- ヒント：「割り切れる」は、余り（`%`）が 0 であることで調べられます。条件を調べる順番に注意してください。15 は 3 の倍数でもあります。

### 演習3-3：成績を判定する

- `grade.rb` を作り、コマンドの引数で受け取った点数から評価を表示してください。
  - 90〜100 → `S`、80〜89 → `A`、60〜79 → `B`、0〜59 → `C`
  - 0〜100 の整数でない入力 → `0から100の整数を指定してください`
- **完了条件**：次の入力に対して、右の出力になる。
  | コマンド | 出力 |
  |---|---|
  | `ruby grade.rb 100` | `S` |
  | `ruby grade.rb 85` | `A` |
  | `ruby grade.rb 60` | `B` |
  | `ruby grade.rb 0` | `C` |
  | `ruby grade.rb 101` | `0から100の整数を指定してください` |
  | `ruby grade.rb abc` | `0から100の整数を指定してください` |
  | `ruby grade.rb` | `0から100の整数を指定してください` |
- ヒント：`case` と範囲（`90..100`）を使うと読みやすく書けます。`"abc".to_i` は `0` になるので、そのままでは `abc` が `C` になってしまいます。数かどうかを確かめる方法を考えてください（例：文字列が数字だけでできているかを調べる、`Integer()` を使う、など）。引数がないときの `ARGV[0]` が何になるかは、`p` で確かめてみてください。

### 演習3-4：数当てゲーム

- `guess.rb` を作ってください。プログラムが 1〜100 の数を1つ決め、利用者が当てるまで入力を受け付けます。
  - 入力が答えより大きければ `もっと小さい`、小さければ `もっと大きい` と表示する
  - 当たったら `正解！N回で当たりました` と表示して終了する
  - 答えは普段は `rand(1..100)` で決めるが、**引数が与えられたときはそれを答えにする**（動作確認のため）
- **完了条件**：次のコマンドの出力の最後の行が `正解！3回で当たりました` になり、その前に `もっと小さい`、`もっと大きい` が1回ずつ、この順で表示される。
  ```console
  printf '50\n25\n37\n' | ruby guess.rb 37
  ```
  また、`ruby guess.rb`（引数なし）で、キーボードから遊べる。
- ヒント：本文の「gets と ARGV の落とし穴」を読み直してください。いつ終わるかわからない繰り返しには `loop` や `while` が向いています。入力の前に表示する案内（`数を入力: ` など）は自由です。

### 演習3-5（発展）：うるう年

- `leap_year.rb` を作り、1990 年から 2030 年までのうるう年を1行ずつ表示し、最後に `合計: N年` と表示してください。うるう年の規則は次のとおりです。
  - 4 で割り切れる年はうるう年
  - ただし、100 で割り切れる年はうるう年ではない
  - ただし、400 で割り切れる年はうるう年
- **完了条件**：`ruby leap_year.rb | tail -n 1` が `合計: 10年` を表示する。出力に `2000` が含まれる。`1900` の判定を確かめるため、範囲を一時的に 1890〜1910 に変えると、`1892`、`1896`、`1904`、`1908` だけが表示される。
- ヒント：規則を `&&` と `||` で1つの条件式にまとめることも、`if` / `elsif` で上から順に判定することもできます。読みやすいと思うほうを選び、なぜそう判断したかをコメントに書いてください。

## 確認クイズ

**Q1.** `puts "3"` と `p "3"` の出力はどう違いますか。デバッグに `p` が向いているのはなぜですか。

**Q2.** 次のプログラムは何を表示しますか。
```ruby
count = 0
puts "カウントあり" if count
```

**Q3.** `"10" + 5` はエラーになります。エラーの種類と、直し方を2つ答えてください。

**Q4.** `7 / 2` の結果は何ですか。`3.5` を得るにはどうしますか。

**Q5.** `(1...4).each { |i| puts i }` は、何行、何を表示しますか。

### 解答と解説

**A1.** `puts "3"` は `3`、`p "3"` は `"3"` と表示します。`p` は文字列を `"` 付きで表示するので、値が文字列なのか数なのか、`nil` なのかを区別できます。デバッグでは、値の中身と型を正確に知りたいので `p` が向いています。

**A2.** `カウントあり` と表示されます。Ruby で偽になるのは `false` と `nil` だけで、`0` は真だからです。「0 なら表示しない」としたいなら、`if count > 0` のように明示します。

**A3.** `TypeError` です。文字列と整数は自動で変換されません。直し方は、`"10".to_i + 5`（整数にして足す、結果は `15`）か、`"10" + 5.to_s`（文字列にしてつなぐ、結果は `"105"`）です。どちらが正しいかは、何をしたいかで決まります。

**A4.** `3` です。整数どうしの割り算は、小数点以下が切り捨てられます。`7.0 / 2` や `7.fdiv(2)` で `3.5` が得られます。

**A5.** 3行で、`1`、`2`、`3` を表示します。`...` は終わりの値（4）を含みません。

## AIの使い方（この章）

この章では、AI を「エラーや文法の解説者」「自分の理解の確認相手」として使います。

推奨する聞き方の例：

- 「Ruby で次のエラーが出ました（エラー全文と、該当する数行を貼る）。答えのコードではなく、エラーメッセージの各部分が何を意味しているかを説明してください」
- 「Ruby の `while` と `loop` と `times` の使い分けについて、私は『回数が決まっていれば times、終わりが事前にわからなければ loop か while』と理解しています。合っていますか。例外的なケースがあれば教えてください」
- 「FizzBuzz を書きました（自分のコードを貼る）。動きは正しいです。読みやすさの観点で、改善できる点を指摘してください。直したコードは書かず、指摘だけにしてください」

この章でやってはいけない使い方：

- **演習の問題文を貼り、答えのコードを書いてもらう。** この章の目的は、自分で条件分岐や繰り返しを組み立てる力を付けることです。AI に書かせると、その力が身につきません。
- **AI の説明を、irb で確かめずに信じる。** AI は Ruby の版による違いを取り違えたり、存在しないメソッドを挙げたりすることがあります。「本当にそう動くか」は、必ず自分で実行して確かめてください。

## まとめ

- Ruby のプログラムは `ruby ファイル名` で実行し、ちょっとした実験は `irb` で行います。
- 値には型があり、整数の割り算や小数の誤差など、型ごとの性質に注意が必要です。型は自動では変換されません。
- `if` / `case` で分岐し、`times` / `each` / `while` / `loop` で繰り返します。偽になるのは `false` と `nil` だけです。
- 入力は `gets`（キーボード）と `ARGV`（引数）で受け取り、どちらも文字列として届きます。
- エラーは「ファイル:行番号」「種類」「メッセージ」の順に読みます。

## 用語

| 用語 | 意味 |
|---|---|
| irb | Ruby の式を1行ずつ試せる対話型の実行環境 |
| 値 / 型 | プログラムが扱うデータ / その種類（Integer、String など） |
| オブジェクト | データと、それに対する操作（メソッド）をまとめたもの |
| メソッド | 値に対して呼び出す操作。`"ruby".upcase` の `upcase` |
| 文字列 / 式展開 | 文字の並び / `"#{ }"` で式の結果を文字列に埋め込むこと |
| nil | 「何もない」ことを表す特別な値 |
| 真偽値 | `true` と `false`。Ruby では `false` と `nil` だけが偽 |
| 変数 / 代入 | 値に付ける名札 / `=` で名札を付けること |
| 定数 | 大文字で始まる名前。変えない値に使う |
| 条件分岐 | 条件によって実行する処理を変えること（`if`、`case`） |
| 繰り返し / 無限ループ | 処理を何度も実行すること / 終わらなくなった繰り返し |
| ブロック | `do ... end` や `{ }` で囲んだ処理のまとまり |
| ARGV | コマンドの引数が入った配列 |
| 標準入力 | プログラムへの入力の流れ。普段はキーボード。`$stdin` |
| エラー / 警告 | プログラムが止まる問題 / 止まらないが注意が必要な問題 |
