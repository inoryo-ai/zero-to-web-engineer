# 第1章 PCとターミナル

> **この章のゴール**：ターミナルでファイルとフォルダを自在に操作でき、Ruby・Git・SQLite・エディタが入った開発環境を自分で用意できる。
> **目安時間**：読む 2時間 ＋ 演習 3時間（環境構築の待ち時間を含む）
> **前提**：なし（この教材の最初の章です）

## この章で学ぶこと

- コンピュータの中で「プログラムが動く」とはどういうことかを、自分の言葉で説明できる
- ファイル・ディレクトリ・パス（絶対パスと相対パス）を区別して使える
- ターミナルで移動・作成・コピー・移動・削除・検索ができ、`Ctrl-C` で止められる
- リダイレクトとパイプで、コマンドの出力を保存したり、別のコマンドに渡したりできる
- 環境変数 `PATH` の役割を説明でき、`which` でコマンドの実体を確かめられる
- Ruby をバージョン管理ツール経由で入れ、Git・SQLite・VS Code と合わせて動作確認できる

## この教材の進め方

この教材は、プログラミングをまったく知らない人が、Ruby と Rails を使うチームで働けるようになるまでを扱います。全27章あり、後半では HTTP サーバやフレームワーク、データベースの仕組みを自分で作ります。最初の数章は、そのための道具の使い方です。地味ですが、ここで身につけた操作は毎日使います。

進め方のルールは3つです。

1. **手を動かす**。読むだけでは身につきません。コマンドは自分で打ち、結果を見てください。コピーして貼り付けるより、打ち込むほうが記憶に残ります。
2. **演習のコードは `~/workspace/` に置く**。章ごとに `~/workspace/ch01` のようなフォルダを作ります。第2章でこのフォルダ全体を Git で管理します。
3. **AIは「解説者・壁打ち相手」として使う**。答えのコードを書かせるのではなく、わからない言葉の説明や、自分の理解の確認に使います。各章の最後に、具体的な聞き方を載せています。

この教材は [speee/training-web-app](https://github.com/speee/training-web-app)（CC BY 4.0）の考え方をもとにしています。その考え方は「抽象を降りて、また登る」です。普段は便利な道具に隠れている仕組みを、一度自分の手で作ってみます。そのうえで、便利な道具に戻ってきます。この章のターミナルは、その「降りる」ための最初の入口です。

## コンピュータの中で何が起きているか

ターミナルを触る前に、コンピュータの中身をざっくり押さえます。後の章で「プロセス」「メモリ」「ファイル」という言葉が何度も出てくるからです。

コンピュータは、大きく4つの部品で考えるとわかりやすくなります。台所にたとえてみます。

| 部品 | 台所でたとえると | 役割 |
|---|---|---|
| CPU | 料理人 | 命令を1つずつ、とても速く実行する |
| メモリ（RAM） | 調理台 | 作業中のデータを置く場所。速いが、電源を切ると消える |
| ストレージ（SSDなど） | 冷蔵庫・食品庫 | ファイルを長く保存する場所。メモリより遅いが、電源を切っても残る |
| OS（macOS、Windows、Linux） | 店長 | 料理人や調理台を、どのプログラムにどれだけ使わせるかを管理する |

**プログラム**とは、CPU にやってほしいことを順番に書いた手順書です。手順書はファイルとしてストレージに保存されています。プログラムを「実行する」と、OS がその手順書をメモリに読み込み、CPU が手順を進めます。この「実行中のプログラム」を**プロセス**と呼びます。同じ手順書から、プロセスを何個も作れます。レシピ（プログラム）は1枚でも、同時に何皿も作れる（プロセス）のと同じです。

ここで大事なのは、**メモリの中身は、プロセスが終わると消える**ことです。プログラムの中で計算した結果を残したいなら、ファイルやデータベースに書き出す必要があります。第15章でデータベースを学ぶ理由の1つがこれです。

もう1つ大事なのは、**OS が「誰が何をしてよいか」を管理している**ことです。ファイルには持ち主と権限があります。他人のファイルや、OS の大事なファイルは、普通のプロセスからは書き換えられません。これは安全のための仕組みです。後で出てくる `sudo`（管理者権限で実行する）を気軽に使ってはいけない理由も、ここにあります。

## ファイルとディレクトリ

### ファイルとディレクトリ

**ファイル**はデータのまとまりで、名前が付いています。文章、画像、プログラムなど、何でもファイルとして保存されます。**ディレクトリ**はファイルを入れる入れ物です。Finder やエクスプローラーで「フォルダ」と呼んでいるものと同じです。この教材では、ターミナルの世界の言い方に合わせて「ディレクトリ」と呼びます。

ディレクトリの中には、ファイルも別のディレクトリも入れられます。そのため、全体は木を逆さにしたような形（**ツリー構造**）になります。一番上の根元を**ルートディレクトリ**と呼び、`/` で表します。

```text
/
├── Applications
├── System
└── Users
    └── taro            ← ホームディレクトリ（~）
        ├── Desktop
        ├── Documents
        └── workspace   ← この教材で作る作業場所
            └── ch01
```

### ホームディレクトリ

ログインしているユーザーごとに、自分専用のディレクトリがあります。これを**ホームディレクトリ**と呼びます。macOS では `/Users/ユーザー名` です。ターミナルでは `~`（チルダ）という短い記号で表せます。この教材の作業場所 `~/workspace` は、「自分のホームディレクトリの中の workspace」という意味です。

### パス：ファイルの住所

ファイルの場所を表す文字列を**パス**と呼びます。住所のようなものです。パスには2種類あります。

- **絶対パス**：ルート `/` から書く住所です。`/Users/taro/workspace/ch01/memo.txt` のように書きます。どこから見ても同じ場所を指します。
- **相対パス**：今いる場所から見た道順です。今 `/Users/taro/workspace` にいるなら、`ch01/memo.txt` で同じファイルを指せます。

相対パスでは、特別な記号を使います。

| 記号 | 意味 |
|---|---|
| `.` | 今いるディレクトリ |
| `..` | 1つ上のディレクトリ |
| `~` | ホームディレクトリ |

たとえば `../ch02` は「1つ上に戻って、ch02 に入る」という意味です。この `..` は、第10章や第11章で学ぶ**パストラバーサル**という攻撃で悪用されます。「`../` を重ねると、本来見せないはずの場所までたどれてしまう」という性質を、今のうちに覚えておいてください。

### 名前の付け方と隠しファイル

ターミナルでは、空白を含む名前は扱いにくくなります。`my memo.txt` と書くと、`my` と `memo.txt` の2つに分かれて解釈されるからです。開発で使うファイル名は、**半角英数字・ハイフン・アンダースコアだけ**にしましょう。日本語の名前も避けたほうが無難です。また、macOS は標準では大文字と小文字を区別しませんが、本番のサーバ（多くは Linux）は区別します。`Memo.txt` と `memo.txt` を混ぜると、自分の PC では動くのにサーバでは動かない、という事故が起きます。

名前が `.`（ドット）で始まるファイルは**隠しファイル**です。普段は表示されません。`.gitignore` や `.zshrc` など、設定ファイルによく使われます。

ファイル名の最後の `.txt` や `.rb` を**拡張子**と呼びます。中身の種類を示す目印です。Ruby のプログラムは `.rb`、Markdown の文書は `.md` です。Finder では拡張子が隠れていることがあるので、設定で表示しておくと混乱しません。

## ターミナルとシェル

### ターミナルとは

**ターミナル**は、文字で命令を打ち込んでコンピュータを操作するためのアプリです。macOS では「アプリケーション → ユーティリティ → ターミナル」にあります。Spotlight（`Command + Space`）で「ターミナル」と入力しても開けます。

マウスで操作できるのに、なぜ文字で操作するのでしょうか。理由は3つあります。

1. **正確に再現できる**：「このコマンドを打つ」と書けば、誰でも同じ操作ができます。マウス操作は説明しにくく、手順書にも残しにくいです。
2. **組み合わせられる**：小さなコマンドをつなげて、複雑な処理ができます。
3. **サーバにはマウスがない**：本番のサーバは画面のないコンピュータです。操作はすべて文字で行います。

### シェルとプロンプト

ターミナルの中で、打った命令を読んで実行しているプログラムを**シェル**と呼びます。macOS の標準のシェルは **zsh** です。Linux では **bash** がよく使われます。ターミナルは「窓口」、シェルは「窓口の奥で注文を聞く係」と考えてください。

ターミナルを開くと、次のような表示があります。

```console
taro@MacBook ~ %
```

これを**プロンプト**と呼びます。「命令をどうぞ」という合図です。`~` は今いるディレクトリ、`%` は入力待ちの印です（bash では `$` が多いです）。この教材では、プロンプト部分を省き、打つ命令だけを書きます。出力例を一緒に見せるときは、`$` を付けて区別することがあります。`$` 自体は打たないでください。

### コマンドの形

コマンドは、基本的に次の形をしています。

```console
コマンド名 オプション 引数
```

- **コマンド名**：何をするか（例：`ls`）
- **オプション**：どのようにするか。`-` や `--` で始まる（例：`-l`）
- **引数**：何に対してするか（例：`~/workspace`）

```console
ls -l ~/workspace
```

これは「`~/workspace` の中身を、詳しい形式（`-l`）で一覧表示する」という意味です。要素の間は半角スペースで区切ります。全角スペースを入れると、別の文字として扱われてエラーになります。日本語入力をオンにしたまま打つと起きやすいので注意してください。

## 基本コマンドを覚える

ここからは、実際にターミナルで打ちながら読んでください。最初は覚えきれなくて当然です。何度も使ううちに指が覚えます。

### 場所を知る・移動する

```console
$ pwd
/Users/taro
$ ls
Desktop    Documents    Downloads
$ ls -a
.    ..    .zshrc    Desktop    Documents    Downloads
$ cd Documents
$ pwd
/Users/taro/Documents
$ cd ..
$ cd
$ pwd
/Users/taro
```

| コマンド | 意味 | 覚え方 |
|---|---|---|
| `pwd` | 今いるディレクトリを表示する | print working directory |
| `ls` | 中身を一覧表示する | list |
| `ls -a` | 隠しファイルも含めて表示する | all |
| `ls -l` | 権限・サイズ・日時付きで表示する | long |
| `cd 場所` | 指定した場所へ移動する | change directory |
| `cd` だけ | ホームディレクトリに戻る | |
| `cd -` | 直前にいた場所に戻る | |

迷子になったら、まず `pwd` を打ってください。「今どこにいるか」を確かめる習慣は、事故を防ぐ一番の方法です。

### 作る・見る

```console
$ mkdir -p ~/workspace/ch01
$ cd ~/workspace/ch01
$ touch memo.txt
$ echo "はじめてのメモ" > memo.txt
$ cat memo.txt
はじめてのメモ
```

| コマンド | 意味 |
|---|---|
| `mkdir 名前` | ディレクトリを作る（make directory） |
| `mkdir -p a/b/c` | 途中のディレクトリもまとめて作る。既にあってもエラーにしない |
| `touch 名前` | 空のファイルを作る（既にあれば更新日時だけ変える） |
| `echo 文字` | 文字を画面に出す |
| `cat ファイル` | ファイルの中身を表示する |
| `less ファイル` | 長いファイルを1画面ずつ読む。`q` で終了、`/単語` で検索 |
| `head -n 5 ファイル` | 先頭の5行だけ表示する |
| `tail -n 5 ファイル` | 末尾の5行だけ表示する |

`tail -f ファイル` は、ファイルに追記される内容をリアルタイムで表示し続けます。後の章でサーバのログを見るときに使います。止めるときは `Ctrl-C` です。

### コピー・移動・削除

```console
$ cp memo.txt memo-backup.txt
$ mv memo-backup.txt old-memo.txt
$ mkdir archive
$ mv old-memo.txt archive/
$ ls archive
old-memo.txt
$ rm archive/old-memo.txt
$ rmdir archive
```

| コマンド | 意味 |
|---|---|
| `cp 元 先` | コピーする。ディレクトリごとなら `cp -r` |
| `mv 元 先` | 移動する。同じ場所での「名前の変更」もこれで行う |
| `rm ファイル` | 削除する |
| `rmdir ディレクトリ` | 空のディレクトリを削除する |
| `rm -r ディレクトリ` | 中身ごと削除する |

**`rm` で消したファイルは、ゴミ箱に入りません。** そのまま消えます。元に戻す方法は基本的にありません。ここは本当に気を付けてください。後の「危ないコマンドとの付き合い方」で詳しく扱います。

### 探す

```console
$ grep "メモ" memo.txt
はじめてのメモ
$ grep -rn "TODO" ~/workspace
$ find ~/workspace -name "*.txt"
```

- `grep 文字列 ファイル`：ファイルの中から、その文字列を含む行を探します。`-r` で中のディレクトリまで探し、`-n` で行番号を付けます。
- `find 場所 -name パターン`：名前でファイルを探します。`*` は「何でもよい文字の並び」を表す記号です。

`grep` は、エンジニアが最もよく使うコマンドの1つです。第12章では、他人の書いた大きなプログラムを `grep` で読み進めます。

### 出力をつなぐ：リダイレクトとパイプ

コマンドの結果は、普通は画面に出ます。これを**標準出力**と呼びます。標準出力は、行き先を変えられます。

```console
$ echo "りんご" > fruits.txt
$ echo "みかん" >> fruits.txt
$ echo "りんご" >> fruits.txt
$ cat fruits.txt
りんご
みかん
りんご
$ sort fruits.txt | uniq
みかん
りんご
$ sort fruits.txt | uniq | wc -l
       2
```

- `>`：出力をファイルに書き込みます。**既にファイルがあれば、中身は上書きされて消えます**。
- `>>`：出力をファイルの末尾に追記します。
- `|`（パイプ）：左のコマンドの出力を、右のコマンドの入力として渡します。

`sort` は並べ替え、`uniq` は隣り合う重複行をまとめる、`wc -l` は行数を数えるコマンドです。1つ1つは単純です。しかし、パイプでつなぐと「重複を除いた種類の数」を数えられます。小さな道具を組み合わせて大きな仕事をする。これは Unix という OS の文化で、後で学ぶ Rack やフレームワークの設計にも通じる考え方です。

エラーメッセージは、標準出力とは別の**標準エラー出力**に出ます。`>` では標準エラー出力は保存されません。両方を保存したいときは `コマンド > out.txt 2>&1` と書きます。今は「出力には2種類ある」とだけ覚えておけば十分です。

### 困ったときの操作

| 操作 | 効果 |
|---|---|
| `Ctrl-C` | 実行中のコマンドを中断する。止まらないと思ったら、まずこれ |
| `Tab` | ファイル名やコマンド名を補完する。打ち間違いが減る |
| `↑` / `↓` | 過去に打ったコマンドを呼び出す |
| `Ctrl-R` | 過去のコマンドを検索する |
| `clear` または `Ctrl-L` | 画面を片付ける |
| `コマンド --help` | 使い方の説明を表示する（コマンドにより `-h`） |
| `man コマンド` | マニュアルを読む。`q` で終了 |

`Ctrl-C` は特に重要です。後の章では、自分で作ったサーバを起動します。サーバは止めない限り動き続けるので、`Ctrl-C` で止めます。画面が反応しなくなったら、慌てずに `Ctrl-C` を押してください。

`Tab` 補完も積極的に使ってください。ファイル名の打ち間違いは、初心者のエラーの大きな原因です。補完が効かないときは、その場所にそのファイルがない、というヒントにもなります。

## 環境変数とPATH

### 環境変数

**環境変数**は、シェルやプログラムが参照する「設定のメモ」です。名前と値の組で、名前は大文字で書くのが習慣です。

```console
$ echo $HOME
/Users/taro
$ echo $SHELL
/bin/zsh
```

`$` を付けると、その環境変数の値を取り出せます。後の章では、環境変数でデータベースの場所やアプリの設定を渡します。パスワードなどの秘密情報も、コードに直接書かずに環境変数で渡すのが一般的です（第20章）。

### PATH：コマンドを探す道順

`ls` や `ruby` と打つと、シェルはそのコマンドの実体（プログラムのファイル）を探しに行きます。どこを探すかを決めているのが、`PATH` という環境変数です。

```console
$ echo $PATH
/Users/taro/.local/share/mise/installs/ruby/4.0.0/bin:/opt/homebrew/bin:/usr/bin:/bin
$ echo $PATH | tr ':' '\n'
/Users/taro/.local/share/mise/installs/ruby/4.0.0/bin
/opt/homebrew/bin
/usr/bin
/bin
$ which ruby
/Users/taro/.local/share/mise/installs/ruby/4.0.0/bin/ruby
```

`PATH` には、ディレクトリが `:` 区切りで並んでいます。シェルは**左から順に**探し、最初に見つかったものを使います（出力例の中身は人によって違います）。`which コマンド名` で、実際にどれが使われるかを確かめられます。

これが重要なのは、同じ名前のコマンドが複数ある場合があるからです。たとえば macOS には、最初から古い Ruby が入っています。後で新しい Ruby を入れても、`PATH` の順番が正しくないと、古いほうが使われてしまいます。「Ruby を入れたのに古いバージョンが動く」というつまずきは、ほぼこれが原因です。困ったら、まず `which ruby` と `ruby --version` を確かめてください。

### シェルの設定ファイル

`PATH` などの設定は、ターミナルを閉じると消えます。毎回同じ設定を使うには、シェルの設定ファイルに書きます。zsh では `~/.zshrc`（とログイン時に読まれる `~/.zprofile`）です。設定ファイルを書き換えたら、ターミナルを開き直すか、`source ~/.zshrc` で読み込み直します。**書き換えても反映されない**、というのもよくあるつまずきです。

## 危ないコマンドとの付き合い方

ターミナルは強力です。強力な道具は、使い方を誤ると大きな事故になります。最初に、守ってほしいことを4つ挙げます。

**1. `rm -rf` は、打つ前に `pwd` と対象を確かめる。**
`rm -rf` は、確認なしに中身ごと削除します。`rm -rf ~/ workspace` のように余計な空白が入ると、ホームディレクトリ全体が対象になります。削除の前には `ls 対象` で、消すものが本当に正しいかを見てください。

**2. `sudo` を気軽に使わない。**
`sudo` は「管理者の権限で実行する」という意味です。OS の大事なファイルも書き換えられます。この教材で `sudo` が必要になるのは、Windows（WSL）でのパッケージ導入くらいです。エラーが出たときに「とりあえず `sudo` を付ける」のは、問題を隠して悪化させるだけです。特に `sudo gem install` は使いません。

**3. 意味のわからないコマンドを貼り付けない。**
インターネットの記事や、AI の回答のコマンドを、そのまま貼り付けて実行するのは危険です。まず `--help` や `man` で意味を調べ、何が起きるかを理解してから実行します。`curl ... | sh` のように「ネットから取ってきたものをそのまま実行する」形は特に注意が必要です。後で Homebrew を入れるときにこの形が出てきます。そのときは、**公式サイトに書かれたコマンドだけ**を使ってください。

**4. 秘密の情報を画面やファイルに出しっぱなしにしない。**
パスワードやトークン（合言葉のような文字列）を `echo` で表示すると、履歴やスクリーンショットに残ります。第2章で GitHub に接続するときも、トークンを手で扱わない方法を使います。

## 開発環境を整える

ここからは、この教材で使う道具を入れていきます。macOS を前提に説明します。Windows の人は、後の「Windows の場合」を先に読んでください。

ここは、この章で一番つまずきやすい部分です。OS のバージョンや PC の種類で、表示が少しずつ違います。エラーが出たら、**エラーメッセージを全部読み、そのまま検索する**のが基本です。第7章で詳しく学びますが、今の段階でもエラーメッセージは大事な手がかりです。

### なぜバージョン管理ツールを使うのか

macOS には最初から Ruby が入っています。しかし、それは使いません。理由は3つあります。

1. **古い**：macOS 付属の Ruby は 2.6 系で、既にサポートが終わっています。この教材は Ruby 3.3 以降を前提にしています（元教材は 4.0 系で動作確認しています）。
2. **OS の持ち物である**：付属の Ruby は OS 自身も使っています。そこに部品（gem）を足そうとすると権限エラーになり、`sudo` で無理に入れると OS の動作を壊すおそれがあります。
3. **プロジェクトごとに版が違う**：実務では、プロジェクトAは Ruby 3.3、プロジェクトBは 3.4、ということが普通にあります。1台の PC で複数の版を切り替える必要があります。

そこで、**Ruby のバージョン管理ツール**を使います。これは、複数の版の Ruby を自分のホームディレクトリの中に入れ、使う版を切り替えてくれる道具です。本棚に Ruby の各版を並べておき、プロジェクトごとに「今日はこの版」と取り出すイメージです。OS の Ruby には触らないので、安全です。

代表的なツールは2つあります。

- **mise**：Ruby だけでなく、Node.js など多くの言語の版を1つの道具で管理できます。この教材では例として mise を使います。
- **rbenv**：Ruby 専用で、長く使われてきた定番です。チームで rbenv を使っているなら、そちらに合わせて構いません。

どちらも、プロジェクトのディレクトリに `.ruby-version` などのファイルを置くと、その場所では自動でその版に切り替わります。両方を同時に入れると、どちらが優先されるか混乱するので、**どちらか1つだけ**にしてください。

### macOS：Command Line Tools と Homebrew

まず、Apple の開発用ツール一式（Command Line Tools）を入れます。Git もここに含まれます。

```console
xcode-select --install
```

ダイアログが出たら「インストール」を押します。既に入っていれば、その旨のメッセージが出ます。

次に、**Homebrew** を入れます。Homebrew は macOS 用のパッケージマネージャです。**パッケージマネージャ**とは、ソフトウェアの入手・インストール・更新をまとめて引き受けてくれる道具です。アプリストアのターミナル版と考えてください。

インストールのコマンドは、必ず公式サイト <https://brew.sh/> に表示されているものをコピーしてください。この教材に書き写したものを使わないのは、「信頼できる出どころのコマンドだけを実行する」習慣のためです。

インストールの最後に、「Next steps」として `PATH` を設定するコマンドが表示されることがあります。Apple シリコン（M1 以降）の Mac では、Homebrew は `/opt/homebrew` に入るので、この設定が必要です。表示されたコマンドを、そのとおりに実行してください。その後、ターミナルを開き直して確かめます。

```console
brew --version
```

`Homebrew 4.x.x` のように表示されれば成功です。

### Ruby を入れる（mise の例）

まず、Ruby をソースからビルド（組み立て）するのに必要な部品を入れます。

```console
brew install openssl@3 libyaml gmp
```

次に、mise を入れて、zsh が起動するたびに mise が働くように設定します。

```console
brew install mise
echo 'eval "$(mise activate zsh)"' >> ~/.zshrc
source ~/.zshrc
```

2行目は、`~/.zshrc` の末尾に1行追記しています。`>>` なので、既存の設定は消えません。ここで `>` と打ち間違えると、`~/.zshrc` の中身が消えます。打つ前に確認してください。

使える Ruby の版を確かめ、3.3 以降の安定版を選んで入れます。ここでは 4.0 を例にします。

```console
mise ls-remote ruby | tail -n 20
mise use --global ruby@4.0
```

`mise use --global` は、「特に指定のない場所では、この版を使う」という設定です。インストールはソースからのビルドになることがあり、数分から十数分かかります。気長に待ってください。終わったら、ターミナルを開き直して確かめます。

```console
which ruby
ruby --version
```

`which ruby` の結果が `/usr/bin/ruby` なら、まだ macOS 付属の Ruby が使われています。`~/.zshrc` の設定と、ターミナルを開き直したかを見直してください。`mise` を含むパスが表示され、`ruby 4.0.x` のように出れば成功です。

**rbenv を使う場合**は、次のようになります。

```console
brew install rbenv ruby-build
echo 'eval "$(rbenv init - zsh)"' >> ~/.zshrc
source ~/.zshrc
rbenv install -l
rbenv install 4.0.0
rbenv global 4.0.0
```

`rbenv install -l` で表示された中から、3.3 以降の安定版を選んでください（上の `4.0.0` は例です）。`which ruby` で `.rbenv` を含むパスが出れば成功です。

### Git と SQLite

**Git** は、ファイルの変更履歴を記録する道具です。第2章で詳しく扱います。Command Line Tools に含まれているので、既に使えるはずです。

```console
git --version
```

新しい版を使いたい場合は `brew install git` で入れられます。必須ではありません。

**SQLite** は、ファイル1つで動く小さなデータベースです。第15章以降で使います。macOS には最初から `sqlite3` コマンドが入っています。

```console
sqlite3 --version
```

版が表示されれば大丈夫です。より新しい版を使いたい場合は `brew install sqlite` で入れられます。

### エディタ（VS Code）

**エディタ**は、プログラムを書くためのアプリです。Word のような文書作成アプリとは違い、余計な書式を付けずに、純粋な文字だけを保存します。この教材では **Visual Studio Code（VS Code）** を使います。無料で、Ruby 用の拡張機能が充実しているからです。

公式サイト <https://code.visualstudio.com/> からダウンロードするか、Homebrew で入れます。

```console
brew install --cask visual-studio-code
```

インストールしたら、次の設定をしてください。

1. **`code` コマンドを使えるようにする**：VS Code を開き、`Command + Shift + P` でコマンドパレットを出します。「Shell Command: Install 'code' command in PATH」を選びます。これで、ターミナルから `code .` と打つと、今いるディレクトリを VS Code で開けます。
2. **Ruby 用の拡張機能を入れる**：左の拡張機能アイコンから「Ruby LSP」を検索して入れます。文法の色分けや、メソッドへのジャンプができるようになります。
3. **保存時の整形を有効にする**：設定（`Command + ,`）で「Insert Final Newline」と「Trim Trailing Whitespace」をオンにします。ファイル末尾の改行と、行末の余分な空白を自動で整えてくれます。差分が読みやすくなり、レビューで指摘されにくくなります。

日本語で使いたい人は「Japanese Language Pack」も入れてください。

### Windows の場合（WSL）

Windows では、**WSL（Windows Subsystem for Linux）** を使います。Windows の中で Linux（Ubuntu）を動かす仕組みです。本番のサーバの多くは Linux なので、実務にも近い環境になります。

管理者として開いた PowerShell で `wsl --install` を実行し、再起動後に Ubuntu のユーザー名とパスワードを設定します。以降のコマンドは、すべて Ubuntu のターミナルで打ちます。Homebrew の代わりに `apt` というパッケージマネージャを使い、Ruby のビルドに必要な部品と Git・SQLite を入れます（ここは `sudo` が必要です）。mise や rbenv の導入手順は、各公式ドキュメントの Linux 向けの説明に従ってください。VS Code は Windows 側に入れ、「WSL」拡張機能から Ubuntu の中のファイルを開きます。ファイルは Windows 側（`/mnt/c/...`）ではなく、Ubuntu のホームディレクトリに置いてください。そのほうが速く、トラブルも少なくなります。

### 確認

最後に、すべてそろったか確かめます。

```console
ruby --version
gem --version
bundle --version
git --version
sqlite3 --version
curl --version
code --version
```

`gem` と `bundle` は、Ruby の部品（gem）を扱う道具で、Ruby と一緒に入ります。`curl` はターミナルから Web ページを取得する道具で、macOS には最初から入っています。どれか1つでも「command not found」と出たら、その道具が入っていないか、`PATH` が通っていません。`which` で確かめ、手順を見直してください。

## 実務ではこうなる

現場に入ると、最初の仕事は「開発環境構築」であることがほとんどです。チームの README に手順が書いてあり、それに沿って PC を整えます。このとき、この章の知識がそのまま試されます。

- **README の手順が古い**のは珍しくありません。手順どおりにやってもエラーになることがあります。そのときに `which` や `--version` で状況を確かめ、エラーメッセージを読んで原因を探せるかが大事です。直せたら、README を直す提案をすると喜ばれます。
- **版の指定はファイルで共有されます**。リポジトリに `.ruby-version` や `mise.toml` が置かれ、全員が同じ版を使います。「自分の PC でだけ動く」を防ぐためです。
- **サーバ作業はすべてターミナル**です。ログを `tail -f` で追い、`grep` で絞り込む場面は日常的にあります。

ジュニアがやりがちな失敗も挙げておきます。

- **`sudo` で押し切る**：権限エラーを `sudo` で回避し、後で原因不明の不具合に悩まされます。権限エラーは「やり方が間違っている」という合図です。
- **どの Ruby が動いているか確かめない**：「さっきまで動いていたのに」という相談の多くは、別のターミナルで別の版が動いていた、というものです。
- **作業ディレクトリを確かめずに削除・上書きする**：`pwd` を打つ一手間で防げます。
- **エラー全文を読まずに「動きません」と相談する**：何をして、何が起きたか、エラーの全文を添えるのが基本です（第7章）。

## 演習

演習の成果は `~/workspace/ch01/` に置きます。

### 演習1-1：ディレクトリを組み立てる

- `~/workspace/ch01/practice` を作り、その中に次の構造を**ターミナルだけで**作ってください。Finder は使いません。
  ```text
  practice/
  ├── docs/
  │   └── readme.txt
  ├── src/
  │   └── main.txt
  └── tmp/
  ```
- 次に、`src/main.txt` を `docs/` にコピーし、コピーの名前を `main-copy.txt` に変えてください。
- 最後に、`tmp/` を削除してください。
- **完了条件**：`find ~/workspace/ch01/practice | sort` の出力が、次の6行と一致する（`/Users/taro` の部分は自分のホームディレクトリ）。
  ```text
  /Users/taro/workspace/ch01/practice
  /Users/taro/workspace/ch01/practice/docs
  /Users/taro/workspace/ch01/practice/docs/main-copy.txt
  /Users/taro/workspace/ch01/practice/docs/readme.txt
  /Users/taro/workspace/ch01/practice/src
  /Users/taro/workspace/ch01/practice/src/main.txt
  ```
  （7行以上あったら、消し忘れや余計なファイルがないか確かめてください）
- ヒント：`mkdir -p` は途中のディレクトリもまとめて作ります。コピーと名前の変更は、`cp` 1回でも、`cp` と `mv` の2回でもできます。

### 演習1-2：リダイレクトとパイプ

- `~/workspace/ch01/fruits.txt` に、`echo` とリダイレクトだけを使って、次の6行をこの順で書き込んでください：`apple`、`banana`、`apple`、`cherry`、`banana`、`apple`。
- パイプを使い、「種類ごとの出現回数」を、多い順に表示するコマンドを1行で書いてください。
- そのコマンド自体を `~/workspace/ch01/count.txt` に保存してください（手で書いても、`echo` で書いても構いません）。
- **完了条件**：`cat ~/workspace/ch01/fruits.txt | wc -l` が `6` を表示する（macOS では数字の前に空白が付きます）。作ったコマンドの出力が、`apple` 3回、`banana` 2回、`cherry` 1回の順で並ぶ。
- ヒント：`uniq` には、重複の数を数える `-c` オプションがあります。`uniq` は**隣り合う**重複しかまとめないので、先に `sort` が必要です。数で並べ替えるには `sort -rn` が使えます。

### 演習1-3：開発環境を整えて記録する

- 本文の手順で、Ruby（3.3 以降）・Git・SQLite・VS Code を入れてください。
- 各ツールの版を `~/workspace/ch01/versions.txt` に記録してください。`ruby --version > ~/workspace/ch01/versions.txt` のように、リダイレクトを使います。2つ目以降は上書きしないように注意してください。
- **完了条件**：
  - `which ruby` の結果が `/usr/bin/ruby` **ではない**。
  - `ruby -e 'puts RUBY_VERSION'` が `3.3.0` 以上を表示する。
  - `versions.txt` に ruby・git・sqlite3・code の4つの版が書かれている（`cat` で確認）。
- ヒント：途中で失敗したら、どのコマンドで、どんなメッセージが出たかをメモしてください。演習1-4と第7章で役に立ちます。

### 演習1-4：PATH を読み解く

- `echo $PATH | tr ':' '\n'` を実行し、自分の `PATH` を1行ずつ表示してください。
- `which -a ruby` を実行してください（`-a` は、見つかったものを全部表示するオプションです）。
- `~/workspace/ch01/path-notes.txt` に、次の3つの問いへの答えを、自分の言葉で書いてください。
  1. 自分の PC には Ruby が何個あったか。それぞれどこにあったか。
  2. `ruby` と打ったとき、そのうちどれが使われるか。なぜそれが選ばれるのか。
  3. 新しく開いたターミナルでも同じ結果になるのは、どの設定ファイルのおかげか。
- **完了条件**：`path-notes.txt` に3つの答えがあり、2つ目の答えが `which ruby` の結果と一致している。

### 演習1-5（発展）：自分用の近道を作る

- `~/.zshrc` に、`ws` と打つと `~/workspace` に移動する**エイリアス**（コマンドの別名）を追加してください。
- **完了条件**：新しいターミナルを開き、`ws && pwd` と打つと `/Users/（自分）/workspace` が表示される。
- ヒント：`alias 名前='コマンド'` という形で書きます。`~/.zshrc` を編集する前に、`cp ~/.zshrc ~/.zshrc.backup` でバックアップを取ってください。編集は `code ~/.zshrc` で VS Code を使うと安全です。

## 確認クイズ

**Q1.** 今 `/Users/taro/workspace/ch01` にいます。`cd ../..` を実行すると、どこに移動しますか。

**Q2.** `echo "hello" > note.txt` を2回実行しました。`note.txt` には何行ありますか。`>>` だったらどうですか。

**Q3.** Ruby 4.0 を入れたのに、`ruby --version` で 2.6 と表示されます。最初に何を確かめますか。考えられる原因を1つ挙げてください。

**Q4.** macOS 付属の Ruby を使わず、mise や rbenv で入れた Ruby を使う理由を2つ挙げてください。

**Q5.** ネットの記事に「これで直ります」と `sudo rm -rf /usr/local/lib/...` というコマンドが書いてありました。どうしますか。

### 解答と解説

**A1.** `/Users/taro` に移動します。`..` は1つ上なので、`../..` は2つ上です。`ch01` → `workspace` → `taro` とたどります。

**A2.** `>` の場合は1行です。`>` は毎回上書きするので、1回目の内容は消えます。`>>` なら追記なので2行になります。大事なファイルを `>` で消してしまう事故はよく起きます。

**A3.** まず `which ruby` で、どの Ruby が使われているかを確かめます。`/usr/bin/ruby` なら macOS 付属のものです。原因としては、`~/.zshrc` に mise（または rbenv）の設定が書かれていない、書いたがターミナルを開き直していない、などが考えられます。

**A4.** たとえば次のような理由です。付属の Ruby は古くサポートが終わっている。OS の持ち物なので gem を入れると権限エラーになり、`sudo` で無理に入れると OS を壊すおそれがある。プロジェクトごとに違う版を切り替える必要がある。

**A5.** すぐには実行しません。`sudo` と `rm -rf` の組み合わせは、取り返しのつかない削除をしうるからです。まず、そのコマンドが何をするか、削除対象が何かを調べます。エラーの原因を理解し、公式ドキュメントなど信頼できる情報で裏付けを取ってから判断します。わからなければ、先輩や講師に相談します。

## AIの使い方（この章）

この章では、AI を「わからない言葉やエラーを解説してもらう相手」として使います。

推奨する聞き方の例：

- 「`ls -la` の出力の、1列目の `drwxr-xr-x` という文字は何を表していますか。初心者向けに説明してください」
- 「`mise use --global ruby@4.0` を実行したら、次のエラーが出ました（全文を貼る）。原因として考えられることを、確かめる方法と一緒に教えてください。修正コマンドをいきなり実行させるのではなく、まず何を調べればよいか知りたいです」
- 「`PATH` について、私の理解は『シェルがコマンドを探すディレクトリの一覧で、左から順に探す』です。合っていますか。足りない点があれば指摘してください」

この章でやってはいけない使い方：

- **AI が出したコマンドを、意味を確かめずに実行する。** 特に `sudo`、`rm -rf`、`curl ... | sh` を含むものは、必ず自分で意味を調べてから判断してください。AI はもっともらしい間違いを言うことがあります。
- **エラーの内容に、パスワードやトークン、個人情報を含めたまま貼り付ける。** 貼る前に中身を確認し、秘密の部分は伏せてください。

## まとめ

- コンピュータは CPU・メモリ・ストレージ・OS で動き、実行中のプログラムをプロセスと呼びます。
- ファイルの場所はパスで表し、絶対パスと相対パス（`.`・`..`・`~`）を使い分けます。
- ターミナルでは、移動・作成・コピー・削除・検索をコマンドで行い、リダイレクトとパイプで組み合わせます。
- コマンドは `PATH` の順に探されます。困ったら `which` と `--version` で確かめます。
- Ruby はバージョン管理ツール（mise や rbenv）で入れ、OS 付属の Ruby には触りません。

## 用語

| 用語 | 意味 |
|---|---|
| プロセス | 実行中のプログラム。OS がメモリと CPU を割り当てる |
| ディレクトリ | ファイルを入れる入れ物。フォルダと同じ |
| ホームディレクトリ | ユーザーごとの専用ディレクトリ。`~` で表す |
| 絶対パス / 相対パス | ルート `/` から書く住所 / 今いる場所から見た道順 |
| ターミナル | 文字で命令を打ってコンピュータを操作するアプリ |
| シェル | ターミナルで打った命令を解釈して実行するプログラム。zsh、bash など |
| プロンプト | シェルが入力を待っていることを示す表示 |
| オプション / 引数 | コマンドの動き方の指定 / コマンドの対象 |
| 標準出力 / 標準エラー出力 | コマンドの通常の出力 / エラー用の出力 |
| リダイレクト | 出力の行き先をファイルに変えること（`>`、`>>`） |
| パイプ | あるコマンドの出力を、別のコマンドの入力に渡すこと（`\|`） |
| 環境変数 | シェルやプログラムが参照する設定の値 |
| PATH | コマンドを探すディレクトリの一覧。左から順に探す |
| パッケージマネージャ | ソフトウェアの導入・更新を引き受ける道具。Homebrew、apt など |
| バージョン管理ツール（Ruby の） | 複数の版の Ruby を入れて切り替える道具。mise、rbenv など |
| `sudo` | 管理者権限でコマンドを実行する指定。気軽に使わない |
